## 오너가 지금까지 준 기준 (공장 40라운드 동안 쌓인 것 — 상용화 판단의 기본값)
1. **뻔하지 않음**(37라운드 1위 이유 "뻔하거나 이미 있음"): 이 게임의 처음 보는 규칙 한 줄이 심장이다. 판의 목표·장애·연출이 모두 그 규칙에서 나와야 한다.
2. **첫인상·손맛**(35·37라운드 "첫인상·손맛이 약함"): 화면이 뜨면 세상이 이미 살아 있고, 첫 손길 1초가 가장 시원한 순간. 결과가 크게(쿵·둥실·와르르).
3. **더 하고 싶게**(37라운드 "더 하고 싶지 않음"): 판을 깨면 모으고 풀리는 것이 보이고, 다음 풀림이 미리 보이고, 별이 모자라면 다시 하고 싶게. 장 끝 보상 장면.
4. **막히지 않게**(38라운드 "1번은 힌트를 넣어주고"): 답은 막혔을 때만 — 전구 힌트가 지금 상태에서 다음 한 수를 한 줄로. 시작 안내는 새것이 하는 일만 말한다.
5. **기획 = 진짜 고민**(38라운드 "기획적 요소를 다듬어야"): 판마다 손댈 것 ≥ 3, 그럴듯한 오답(함정), 순서·때가 중요. 버릇 하나로 ★3이 나오면 안 된다(3판부터 버릇 봇 ★3 < 50%).
6. **조작은 쉽게**(33라운드 "조작이 어색하거나 어려움"): 톡(또는 톡 → 톡). 꾹 모으기·좁은 타이밍·당겨 겨누기·연타·문지르기 금지. 손가락이 3% 어긋나도 점수 ≥ 0.7.
7. **소리**(38라운드부터): 모든 사건에 효과음, 높낮이로 크기, 연쇄는 음이 올라가게. 끄기 단추.
8. **그래픽·연출은 상용 수준**: 직접 그린 캐릭터(표정·반응), 밝은 낮, 층 있는 배경, 멈칫·흔들림·파티클. 큰 글자는 한 번에 하나(겹치면 안 읽힘).
9. **너무 어렵지 않게**: 첫 판은 거의 못 진다, 처음 10초는 안 해도 잃지 않음, 실패하면 그 판만 다시.
10. **쉬운 말**: 목표·별·지는 조건은 기호 없는 한 줄, 단계별로 하나씩 배우게(나사 공방 M2·M3).
11. **화면이 읽힌다·폰에서 가볍게**: 390px에서 글자 12px 이상, 주인공 크게. CPU 4배 느림에서 게임 코드 한 프레임 중앙 ≤ 8ms·p95 ≤ 16ms(`arcade/kit/frame-check.cjs`).
12. **먼저 졸업한 팀들의 결과**(참고): 졸업한 열 팀이 모두 끝남 — 🥷 느린 시간 닌자(실시간 액션, 가장 오래 감: M3 → F8 뒤 2026-11-21 오너 "폐기하자" · "내리고 지워버리고 세션도 꺼버려") · ⚔️ 동물 군단(스튜디오가 '정해진 카드 줄 퍼즐'로 바꾼 뒤 M1에서 폐기) · 🔩 나사 공방(M3″ "한계가 좀 보인더") · 🧪 물약(M0 "이미 너무 뻔하게 있는") · 🚌 버스·💥 철거·🎈 풍선·🐑 양치기(M1 안팎 폐기) · 🦆 욕조·🪐 행성(예약 꺼짐). 공통 교훈: **코어 손맛을 퍼즐·카드 고르기로 바꾸면 버려진다**(동물 군단) · **그림을 다듬는 데 마일스톤을 여럿 쓰면 지친다**(닌자 F1~F8은 머리 모양·도트 글 고치기가 대부분) — **매 마일스톤에서 코어 재미·첫인상·그림이 바로 느껴져야 한다.**

## ★ 오너의 이번 요구: "AAA 게임급으로" (이 브리프의 1순위)
오너가 처음으로 품질 등급을 콕 집었다. 지금까지의 '상용화 수준'보다 한 단계 위 — **대형 스튜디오가 만든 것처럼 보이고, 들리고, 손에 붙는** 게임. 웹 캔버스(설치 없이 폰 브라우저)라는 틀은 그대로지만, 그 안에서 할 수 있는 최고를 한다. 기준(마일스톤마다 👁·🧪·📋가 이 표로 점검):

| 축 | AAA 기준 (이 게임에서) |
|---|---|
| **아트 디렉션** | 한 장의 아트 바이블(`ART.md`)로 통일된 세계관·팔레트·조명·재질. 귀여운 스티커가 아니라 **입체감 있는 그림**: 형태에 명암 3단(밝은 면·중간·그림자) + 가장자리 빛(림 라이트) + 바닥 접지 그림자(AO). 장마다 시간대·날씨·조명이 다른 무대, 전경·중경·원경 3층 이상 시차, 배경이 살아 움직임(관중·깃발·물결·나뭇잎). |
| **캐릭터·애니메이션** | 몸 13+가지 모두 **뼈대 애니메이션**(코드로 관절·스프링): 대기 숨쉬기, 걷기, 공격 예비 동작(안티시페이션) → 타격 → 여운(팔로스루), 맞음·기절·쓰러짐, 유령이 들어갈 때의 변신 연출. 찌그러짐·늘어남(스쿼시·스트레치), 표정 변화. 유령 주인공은 감정이 읽히는 얼굴(신남·겁먹음·의기양양). |
| **타격감(게임 필)** | 크기별 히트스톱(0.03~0.12초), 카메라 흔들림 단계, 임팩트 프레임(흰 실루엣 한 장), 넉백·회전·튕김, 큰 순간엔 잠깐 느려짐 + 카메라 줌 인, 연쇄가 커질수록 화면·소리·글자가 커지는 사다리. 입력 → 첫 반응 ≤ 1프레임. |
| **이펙트(VFX)** | 펑·충격파·먼지·파편·빛 번짐(가산 합성 글로우)·잔상·궤적. 몸마다 고유 이펙트 색과 모양. 대장 등장·보호막 깨짐·대장 타기는 '컷신급' 연출(2~4초, 건너뛰기 가능). |
| **사운드·음악** | 효과음은 층을 쌓아(타격음 + 저음 쿵 + 고음 반짝 + 공간 울림) 몸마다 다르게, 연쇄는 음이 올라감. **음악**: 코드로 합성하는 적응형 배경음악(평소 → 전투가 붐비면 층이 늘어남 → 대장전 테마 → 승리 팡파르). 소리·음악 크기 따로, 끄기 기억. 샘플 파일을 쓰면 직접 만든 것만(외부 음원 금지). |
| **UI·UX** | 타이틀 화면(살아 있는 장면 + 로고), 월드 지도(장·판 진행·별·대장), 일시정지·설정(소리·음악·진동·화면 흔들림 줄이기), 결과 화면 연출(별이 하나씩 쾅·숫자 굴러감·보상 뿌림), 버튼 누름 반응·전환 애니메이션. 글자는 직접 고른 굵은 둥근 글꼴 스타일로 통일, 아이콘 세트 하나. **첫 30초 온보딩**은 글 없이 손가락·연출로. |
| **콘텐츠 양** | 최종 목표: 월드 5 × 판 8~10 + 월드마다 대장(= 45판 안팎), 몸 24가지 이상(각 고유 행동·기술·강화 단계), 무한 모드(마당 버티기)·일일 도전, 도감·업적·유령 꾸미기. 오래 해도 새로 할 것이 계속 나온다. |
| **메타·성장** | 유령 레벨 + 몸 강화(같은 몸을 여러 번 타면 도감 별이 오르고 기술이 진화) + 장 끝 둘 중 하나 + 꾸미기(모자·꼬리 불꽃). 저장은 기기에(localStorage, 불가해도 동작). |
| **성능·완성도** | 중간급 폰에서 60fps(CPU 4배 느림에서 게임 코드 p95 ≤ 12ms, `arcade/kit/frame-check.cjs` 본떠 측정), 첫 화면 2초 안, 콘솔 에러 0, 360·390·430px·가로 태블릿, 라이트 환경에서 읽힘. 번들 크기는 팀이 정하되(예: gzip 400KB 이하) 이유를 적는다. 런타임 의존성 금지 — 필요하면 WebGL도 직접 짠다(빛·글로우를 위해). |
| **QA** | 결정적 시뮬레이션 유지(봇으로 밸런스), 무작위 톡 10분 막누르기에 오류·멈춤 0, 모든 판을 잘하는 봇·막누르는 봇으로 끝까지. |

- **AAA는 '많이'가 아니라 '전부 다듬어져 있음'이다.** 판 하나·몸 하나라도 덜 된 것이 보이면 AAA가 아니다. 그래서 **M1은 '버티컬 슬라이스'**: 첫 월드 하나(판 4 + 대장)를 위 표의 모든 축에서 최종 품질로 끝낸다 → 오너 테스트 허들 "**첫 5분이 대형 게임처럼 보이고 들리고 손에 붙는가**". 그 뒤 마일스톤은 슬라이스의 품질을 유지하며 양을 늘린다.
- 코어 손맛(톡 = 갈아타기, 버린 몸 펑, 몸이 저절로 싸움)은 **바꾸지 않는다**. 카드 고르기·퍼즐·정답 있는 판·수 제한으로 바꾸면 버려진다(동물 군단·39라운드 교훈).

## 마일스톤과 오너 테스트 (오너 지시의 핵심)
1. **M0(첫 사이클~두 사이클)**: 프로토타입을 `studio/bodyhop/`로 옮겨 플레이 빌드를 `web/public/studio/bodyhop/index.html`에 올린다(지금 모습 그대로 — 오너가 재밌다고 한 것). 기획자 GDD 초안, **아트 디렉터 아트 바이블 초안**(`ART.md`: AAA 표의 아트·애니메이션·이펙트 원칙을 이 게임 말로), 사운드 디자이너 `AUDIO.md` 초안, PM 마일스톤 초안 — **M1 = 첫 월드 버티컬 슬라이스(판 4 + 대장)를 AAA 표 모든 축에서 최종 품질로**, 허들 "첫 5분이 대형 게임처럼 보이고 들리고 손에 붙는가". M2~M5는 품질을 지키며 월드·몸·모드·메타를 늘린다(마일스톤마다 **테스트 허들**=오너가 무엇을 확인하면 통과인지 명시).
2. 마일스톤마다: 기획(📐) → 디자인(🎨) → 개발 → FUN QA(🧪) → PM QC(📋). 완료 기준·QC를 다 넘으면 PM이 **"오너 빌드 테스트 준비 완료"** 선언.
3. 그 사이클에만 `PushNotification`(무엇을 테스트할지 3줄 + 전체 주소 https://derrick1119.github.io/derrickkim1119/studio/bodyhop/) 하고 STATUS `상태: 오너 테스트 대기`. 기다리는 동안은 새 기능을 만들지 않는다(한 줄 보고).
4. 오너가 **통과**라고 하면 다음 마일스톤. **허들 미달**이면 오너 피드백을 STATUS·TALK에 그대로 적고, PM이 **마일스톤을 재수립**(무엇을 어떻게 고치고 언제 다시 테스트할지)한 뒤 진행한다.
5. 최종 목표: **AAA 게임급**(오너) — 위 AAA 표를 모든 월드·몸·화면에서 만족, 출시해도 되는 품질(온보딩·콘텐츠 볼륨·메타·저장·사운드·음악·성능·접근성·모바일). 마지막 마일스톤 통과가 졸업.

## 사이클 (예약 작업, 1시간마다 — 발견 공장이 만들어 이 세션에 연결해 둠)
- 동기화(`git fetch origin factory && git checkout factory && git pull --rebase origin factory`, 필요하면 `npm ci`) → STATUS·MILESTONES·TALK 맨 위 읽기 → 멈춤 확인(`오너 테스트 대기`면 오너 피드백이 있을 때만 반영, 없으면 한 줄 보고) → 이번 마일스톤 작업 1~2개(크면 쪼개되, AAA 품질 작업은 한 사이클에 '한 화면이 눈에 띄게 좋아짐'이 보이게) → 측정(build·funqa·shots·verify) → 👁 화면 비평 루프([치명]·[큼] 고치고 다시 찍기) → FUN QA → 응답 → PM → 기록 → 커밋·푸시 → 배포 확인.
- 사이클 끝 한국어 3줄 요약. **오너에게 보이는 첫 줄은 플레이 주소 https://derrick1119.github.io/derrickkim1119/studio/bodyhop/**.
- 오너와 대화는 한국어로만.

## 결과물 위치와 공개
- 코드·문서: `studio/bodyhop/`, 테스트: `tests/studio-bodyhop*.test.ts`
- 플레이 빌드: `web/public/studio/bodyhop/` → `factory` 브랜치에 push하면 GitHub Pages 자동 배포: **https://derrick1119.github.io/derrickkim1119/studio/bodyhop/** (오너가 승인한 공개 주소. 이 환경에서는 github.io 직접 접속이 막혀 있으니 배포 확인은 GitHub Actions `deploy` 결과로.)
- 공용 테스트가 무거워 CI에서 vitest 시간 초과가 가끔 난다 — 이 팀의 테스트는 가볍게(판별 측정은 표본을 작게) 유지한다.

## 가드레일
- 수정할 수 있는 곳은 `studio/bodyhop/`, `web/public/studio/bodyhop/`, `tests/studio-bodyhop*.test.ts` **뿐**. 다른 작업장(`arcade/`, `studio/` 다른 게임, `factory/`, `engine/`, `fusion/`, `web/index.html` 등)은 고치지 않는다.
- `npm run verify` 실패 상태로 push 금지(종료 코드로 판정, 출력을 파이프로 거르지 않는다). 테스트 약화·삭제·skip 금지. push가 거절되면 `git pull --rebase origin factory` → verify → push. force push 금지. `factory` 브랜치에만. 다른 팀의 작업 파일을 stash·checkout으로 건드리지 않는다.
- 런타임 의존성 추가 금지(번들은 esbuild 등 개발 도구로). 외부 서비스 가입·결제·광고 SDK 연동 금지. 비밀값을 저장소에 쓰지 않는다.
- 특정 실존 게임의 이름·캐릭터·아트·레벨을 가져오지 않는다. 결정적 시뮬레이션(봇으로 밸런스 측정)을 유지한다.
- 커밋 메시지: "스튜디오 몸 갈아타기: <요약>" (모델 이름을 넣지 않는다).
- 연속 3사이클 verify 실패로 push 못 하면 STATUS `상태: BLOCKED` + 이유 + 알림.
