- **완료 기준**: 저장/복원 테스트(새로고침 후 별·도토리·꾸미기·진열장 유지) · localStorage 예외 테스트 · 오늘의 주문 결정성(같은 날짜 = 같은 판) + 장인 클리어 1.0 · 꾸미기 ≥ 12종 · 30판 기준 도토리 수급이 꾸미기 절반 이상을 살 수 있는지(경제 시뮬) · 에너지·하트·대기 타이머 0.
- **오너 테스트 허들**
  1. 판을 몇 개 깨고 앱을 닫았다 다시 열어도 별·진열장·꾸미기가 그대로다.
  2. 진열장에 장난감이 늘어나는 게 보기 좋고, ★3 받침대를 위해 다시 하고 싶은 판이 생긴다.
  3. 오늘의 주문 1판을 하고 "내일도 와 볼까"가 든다.
  4. 돈·광고 압박(대기·하트·팝업)이 하나도 안 느껴진다.

## M5 상용화 = 졸업 (5사이클, 한도 8)
- **포함**: 월드 4~6(공룡·성·우주) 30판 → **총 60판**(오너 승인 볼륨에 맞춘다), 남은 특수 요소(스프링·째깍·M2에서 고르지 않은 신규 후보), ★3 '톡 T번' 정식. 온보딩 마감(GDD §10: 첫 3초에 타이틀 없이 1-1, 손가락 톡 → 꾹 유도, 규칙 2줄은 결과 화면에서). 설정(소리·진동·다시 보기). 접근성(색 + 무늬, 키보드만으로 전 판, 글자 대비, 줄어든 움직임 옵션). 성능(첫 표시 ≤ 2초 가정, 30fps). 모바일 마감(세이프 에어리어, 가로 회전 안내, 백그라운드 일시정지). 오프라인 동작.
- **완료 기준**: 60판 전부 GDD §13.1 · 처음 봇 1-10 도달 ≥ 0.7 · 키보드 E2E 1판 클리어 · 다크/라이트(또는 단일 테마 대비 기준 충족) · 390px·데스크톱 스크린샷 전 화면 · 콘솔 에러 0 · gzip ≤ 30KB(또는 오너 승인 상향) · 실존 게임과 이름·UI·레벨 닮음 점검표 통과.
- **오너 테스트 허들(졸업)**
  1. 처음 보는 사람에게 휴대폰을 건네도 설명 없이 30초 안에 플레이를 시작하고 웃는다.
  2. 60판 중 월드 4~6에도 새것이 계속 나와 끝까지 질리지 않는다.
  3. 저장·소리·설정·키보드·느린 폰까지 "출시해도 되겠다"에 걸리는 게 없다.
  4. 같은 장르 시장 게임과 나란히 놓아도 진자·장난감 공방·밤톨 때문에 "이건 다른 게임"이다.

3. funqa 최신(이번 빌드)이고 시드 ≥ 12다. 이전 마일스톤 지표가 퇴행하지 않았다(장인 클리어 1.0, 무작위 1판 ≥ 0.98, 버릇 ★3 상한).
4. 390×844 스크린샷을 PM·🧪가 직접 보았다. 가로 스크롤 0, 콘솔 에러 0, 손가락에 가리는 핵심 정보 없음, 글자가 390px에서 읽힌다.
5. 키보드만으로 1판을 클리어할 수 있다. localStorage 차단에서도 동작한다.
6. 규칙 문장은 2줄(+판별 팁 한 줄)이고, 첫 방문자가 30초 안에 이해한다(🧪 처음 하는 사람 관점 평가).

8. gzip ≤ 30KB다(M1′ 동안은 ≤ 36KB — 2026-11-14 재수립, 이유는 M1′ 위험 ①). 수정 범위는 `studio/screwshop/`·`web/public/studio/screwshop/`·`tests/studio-screwshop*.test.ts`뿐이다.

10. STATUS '오너에게'에 무엇을 해 볼지 3줄과 전체 주소를 적는다. 열린 오너 질문은 따로 표시한다.

## 재수립 규칙 (허들 미달 시)
- **R1 그대로 적기**: 오너 피드백 원문을 STATUS·TALK에 그대로 적는다(요약·해석 금지). 마일스톤 상태는 "재수립"으로 둔다.
- **R2 진단 1사이클**: 📐·🧪가 피드백을 허들 번호와 오너 기준(1~13)에 대응시킨다. 봇 지표로 재현되는지 확인한다(재현 안 되면 지표·봇을 먼저 고친다. 지표가 틀린 것이다). 이 사이클은 일정에 넣지 않는다.
- **R3 다시 쓰기**: PM이 해당 마일스톤을 Mn′로 다시 쓴다. 무엇을 고치는지(허들 문장 단위), 새 완료 기준(숫자), 다시 테스트할 사이클을 정한다. 원래 범위의 남은 항목은 다음 마일스톤으로 넘긴다. 범위는 늘리지 않고 고칠 것만 남긴다. 다시 테스트는 **원래 사이클 수의 절반 이하**로 잡는다.
- **R4 같은 이유로 두 번 미달**하면 그 요소(예: 진자, 특정 특수 판자)를 "바꾸기 vs 빼기" 두 안으로 STATUS '오너에게'에 묻는다. 다듬기만 반복하지 않는다(기준 10 "같은 걸 다듬기만 함").
- **R5 한도 초과**: 마일스톤이 150% 한도에 닿으면 남은 ❌를 오너에게 밝히고 테스트를 요청하거나, 범위를 줄여 다음 마일스톤으로 넘긴다. 몰래 늘리지 않는다.
- **R6 폐기 신호**: 오너가 M1에서 "코어가 재미없다"는 취지로 미달을 주면(🎈 선례), R3 전에 진자 규칙 자체를 바꾸는 안 2개를 📐가 내고 오너가 고르게 한다.
