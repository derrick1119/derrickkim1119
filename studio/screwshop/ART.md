# 🎨 ART: 손맛(쾌감) 설계 v1 (M0 오너 피드백 대응)

> 오너 원문: "재밌네 근데 뭔가 쾌감이 좀 부족해 기믹도 좀 부족한거 같아". 🎨는 **쾌감(손맛)** 을 맡고, 기믹 규칙은 📐가 맡는다.
> 기준 수치(390px 화면): 1틱 = 16.7ms(60틱 고정). 캔버스 폭 w = 390이라 R(0.01) = 3.9px다. 나사 반지름 12.5px, 상자 폭 97px. 톡에서 쏙까지 26틱(433ms) 걸린다.
> 원칙: 연출과 소리는 **draw의 이벤트 루프에서만** 부른다. 시뮬레이션 상태는 건드리지 않고, RE 기록에 필드만 더한다. 그래서 봇·결정성·funqa는 그대로다.

## 1. 진단: 쾌감이 부족한 이유 5개

1. **귀와 손이 비어 있다.** 소리 0, 진동 0이다. 나사 풀기의 손맛은 "드르륵 → 뽁 → 쏙" 3박인데 셋 다 무음이다. 아이폰은 진동 API가 없으니 손맛을 주로 맡을 것은 소리다.
2. **'딱' 하는 순간이 없거나 어긋난다.** 화면이 멈추는 순간(히트스톱)이 0프레임이라 모든 것이 흘러가 버린다.
   - (a) 나사가 구멍을 떠나는 순간(t0+9)에 아무 일도 일어나지 않는다.
   - (b) 상자 착지 연출이 크림색 점 10개(나사 색이 아님)와 상자 4.7px 들썩임뿐이다.
   - (c) 상자 닫힘의 burst 22·흔들림 2.5가 뚜껑이 닫히기 *시작할 때*(tc) 터진다. 뚜껑이 실제로 닿는 tc+8에는 아무것도 없다.
   - (d) 덜컹은 흔들림이 두 번 온다. 떨어지기 시작할 때 6, 작업대에 닿을 때 5로, 큰 쪽이 먼저다. 톱밥도 두 번 나온다(첫 번째는 판자가 아직 공중에 있을 때).
3. **입력 첫 프레임의 반응이 약하다.** 누르면 흰 고리만 생기고 눌리는 느낌이 없다. 떼면 나사 크기가 1.0에서 9틱에 걸쳐 1.35로 커지기 때문에, 손을 뗀 첫 프레임에는 거의 변화가 없다. 그래서 입력과 반응 사이가 늦게 느껴진다.
4. **쌓이는 맛이 0이다.** 연속 1번째 쏙과 8번째 쏙이 똑같다. 연속 표시는 3·C·C+4k번째에만, 그것도 작업대 오른쪽 아래(X 0.82, Y 1.27)에 16px로 뜬다. 시선은 맨 위 상자에 있어서 거의 안 보인다. 아래 띠의 "지금 연속 N"도 12px다.
5. **와우와 마무리가 조용하다.** 진자 빙글(우리 정체성)은 고리와 14px "빙글~"뿐이다. 마지막 나사도 평소 속도로 지나간다. 실패는 빨간 번쩍과 흔들림 8·9라서 벌처럼 느껴진다(기준 3과 어긋남).
   - 덤(버그): `Juice.render`가 *화면 프레임마다* 파티클·글자·흔들림을 움직인다. 그래서 120Hz 폰에서는 파티클이 2배 빨리 사라진다. 손맛이 좋은 폰일수록 오히려 약해진다.

## 2. 쾌감 순간 표 (핵심)

### 2.1 소리 재료: 합성 원형 5개 (WebAudio, 샘플 파일 없음, 표의 칸이 이 이름을 쓴다)

- **M(f) 마림바 톡**: 사인 f(어택 3ms, 지수 감쇠 220ms, 0.38) + 사인 3.98f(45ms, 0.12) + 노이즈 하이패스 4kHz(8ms, 0.08). 나무 실로폰 소리로 쏙을 낸다.
- **R 래칫 드르륵**: 노이즈 → 밴드패스 Q8. 클릭 5번을 30ms 간격(0·30·60·90·120ms)으로 낸다. 클릭마다 12ms 지수 감쇠, 중심 2400→4200Hz(+450씩), 크기 0.14→0.30.
- **P 뽁**: 사인 380→980Hz 지수 70ms 0.32 + 노이즈 하이패스 2kHz 20ms 0.10. 코르크가 빠지는 소리다.
- **T(f) 나무 쿵**: 삼각파 f→0.45f 지수 160ms 0.5(로우패스 900Hz) + 노이즈 로우패스 1.2kHz 50ms 0.22.
- **K 끼익**: 톱니파 95→70Hz 380ms → 밴드패스 1.1kHz Q9(LFO 사인 11Hz, ±250Hz로 주파수를 흔듦). 어택 40ms, 200ms까지 유지, 380ms에 0. 크기 0.22.
- **공통 설정**
  - 마스터 0.5 → DynamicsCompressor(threshold −14dB, knee 6, ratio 4, attack 3ms, release 120ms)로 겹쳐도 깨지지 않게 한다.
  - 같은 소리가 25ms 안에 또 오면 하나로 합친다.
  - 노이즈 버퍼는 0.5초짜리 하나를 만들어 재사용한다.

### 2.3 구현 메모

- **새 이벤트**: `playRec`의 box·slot 분기에서 `ev(s,'twist',px,py,…,t0)`, `ev(s,'pluck',px,py,…,t0+SPIN)`. drawAll의 `due` 종류 목록에도 둘을 추가한다.
- **RE 필드 추가**: `place()`에서 box에 `n: S.streak`, slot에 `lost: S.streak`(0으로 되돌리기 *전* 값)를 담는다. `in`·`slot` 이벤트의 text로 넘긴다.
- **소리 훅**: game.ts에 `export let onCue = (c: Cue, v?: number) => {}` + `setCue()`(🐑 sfx 방식). 이벤트 루프에서 연출과 같은 줄에 `onCue(kind, v)`를 부른다. 누름은 `fx.memo.pk !== pressK`, 진자 되돌이는 `fx.memo['sg'+k]` 부호로 감지한다.
- **멈춤·시계** (juice.ts + main.ts)
  - `Juice.hold(n)`은 `stop = max(stop, n)`.
  - main 루프에서 `latch = null` *앞에* `if (j?.stop) { j.stop--; acc -= TICK; continue; }`를 둔다. 누른 입력을 잃지 않기 위해서다.
  - 슬로모는 `s.phase==='settle' && s.ok && s.pt<40`일 때 틱을 하나 걸러 건너뛴다.
  - **120Hz 보정**: `render(ctx,w,h,n)`에서 n = 이번 프레임에 쓴 1/60 조각 수(멈춘 조각 포함)만큼만 파티클·흔들림을 진행한다.
  - `prefers-reduced-motion`이면 흔들림 ×0.3, 멈춤 0, 번쩍 ×0.3.
- **진동**: `buzz(p)`는 꺼져 있거나 `!navigator.vibrate`면 무시한다. 45ms 안에 또 오면 버린다. 첫 사용자 입력 뒤에만 부른다.

## 3. 연속 쏙 누적감

- **음계**(5음계라 겹쳐도 불협이 없다): f(n) = 523.25 × 2^((12·⌊(n−1)/5⌋ + [0,2,4,7,9][(n−1)%5]) / 12)
  - n = 1~11 → C5 523 · D5 587 · E5 659 · G5 784 · A5 880 · C6 1047 · D6 1175 · E6 1319 · G6 1568 · A6 1760 · C7 2093. 12 이상은 C7에 고정한다.
- **숫자 팝**: 착지한 상자 앞판(Y = BOX_Y+0.03)에서 40틱 동안 24px 떠오른다. 크기 = min(36, 14 + 2.6n)px이고, 처음 6틱은 1.6→1.0 펀치(juice Popup에 3줄 추가). 지금의 오른쪽 아래 `streak` 팝과 "지금 연속 N" 글자는 지운다.
- **칩 게이지**: 아래 띠 "연속 쏙 C" 칩 안을 왼쪽부터 min(n,C)/C만큼 채운다(연두 .35, C에 닿으면 금 .5). 쏙마다 칩이 1.08배로 맥박친다(6틱).

## 5. 소리 끄기 토글과 자동재생

- **위치**: HTML 헤더(캔버스 밖, 화면 맨 위 44px 띠)의 오른쪽 끝. **🔊 44×44 버튼**을 오른쪽 여백 8px에 둔다. 그 왼쪽에 **📳 44×44 진동 버튼**을 두되, `navigator.vibrate`가 없으면(아이폰) 숨긴다.
  - 엄지가 움직이는 판 영역(화면 y 약 190~520px)과 아래 띠에서 멀어서 플레이 중에 손가락에 가리거나 잘못 눌리지 않는다.
  - 지금의 "스튜디오 빌드 M0" 작은 글씨는 타이틀 오버레이 아래로 옮긴다(390px에서 제목 약 170px + 버튼 2개 + 여백이 들어가게).
- **상태 표시**: 🔊/🔇 아이콘, `aria-pressed`, `aria-label`("소리 끄기"/"소리 켜기"). 키보드는 **M**이다. `localStorage 'screwshop:mute'`, `'screwshop:buzz'`에 저장하고(try/catch, 막혀 있으면 기본 켬), 소리를 켜는 누름에서 미리 듣기 쏙을 한 번 낸다.
- **자동재생 정책**
  - AudioContext는 **타이틀 '시작' 클릭 핸들러 안에서** 처음 만든다(`sfx.wake()`). 페이지가 로드될 때는 절대 만들지 않고, 꺼 둔 상태면 아예 만들지 않는다. 첫 소리는 그 시작 클릭의 "딸"이다.
  - `pointerup`·`keydown`마다 wake()로 suspended/interrupted 상태를 복구한다(아이폰은 무음 1샘플). `visibilitychange` hidden이면 `ac.suspend()`.
  - `navigator.audioSession?.type = 'ambient'`로 iOS 17+의 무음 스위치를 존중하고, 듣던 음악과 섞이게 한다.
  - 진동도 첫 사용자 입력 뒤에만 낸다.

## 6. 실존 게임을 닮지 않게 하는 원칙 (2줄)

1. **소리 재료는 '나무 공방'에서만 가져온다**: 마림바·목탁·래칫·나무 쿵·장난감 종. 8비트 사각파 코인 2음, 슬롯머신 롤링, 영어 칭찬 낭독(Great!/Perfect!), 특정 게임의 시그니처 징글·음 순서는 쓰지 않는다. 연속 음계는 우리가 정한 5음계 C5→C7이고, 🐑의 C-E-G 팡파르·"와와와" 실패음과도 겹치지 않게 했다.
2. **칭찬은 공방 사물이 한다**: 숫자는 상자 앞판에서, 연속은 햄스터 망치 장단과 상자 빛으로, 완성은 장난감 리빌로 보여 준다. 화면을 가득 채우는 'PERFECT' 리본, 무지개 콤보 바, 장르 관용 결과창 배치는 그대로 쓰지 않는다.

**자리** (판자 로컬, 작업판 단위)

- 히트 판정(P.ham, hamP, hamT)과 1판 좌표는 그대로 둔다.
```ts
function hamEdge(P: Src) { // → [ex, ey, an]: 가장자리 점 + 바깥 법선 각
  const dx = P.ham![0] - P.cx, dy = P.ham![1] - P.cy, c = Math.cos(P.a), s = Math.sin(P.a);
  const lx = dx * c + dy * s, ly = -dx * s + dy * c, end = Math.abs(lx) / P.hx >= Math.abs(ly) / P.hy;
  return end ? [Math.sign(lx) * P.hx, ly, lx >= 0 ? 0 : Math.PI] : [lx, Math.sign(ly) * P.hy, ly >= 0 ? Math.PI / 2 : -Math.PI / 2];
}
```
**때리는 면 F** (geometry에서 hamP 옆에 `hamF`로 계산)
- 처음으로 칠 수 있는 매달림 자세에서 머리가 움직이는 쪽을 F로 한다.
```ts
const qi = Math.max(1, hamT[k].findIndex((a) => a.length)), q = poses[k][qi], an = hamEdge(p)[2], sg = Math.sign(q.d) || 1;
const mx = -(p.ham[1] - q.py) * sg, my = (p.ham[0] - q.px) * sg, th = p.a + an;
hamF[k] = -Math.sin(th) * mx + Math.cos(th) * my >= 0 ? 1 : -1;
```
- 1판으로 확인한 값: 머리 +1(면이 아래), 꼬리 −1(면이 왼쪽 아래), 몸통 −1(면이 오른쪽). 셋 다 치러 가는 쪽을 본다.

- 머리 축(+y = 때리는 쪽)은 M → 과녁 방향이다. 그래서 금색 호가 끊기지 않고 머리로 들어가고, 면 띠는 과녁 가장자리 1.5px 앞에서 과녁을 정면으로 본다.
```ts
const hitAt = (q: Pose, i: number, r: number) => {
  const sg = Math.sign(q.d) || 1, rT = Math.hypot(L.px[i] - q.px, L.py[i] - q.py), a = Math.atan2(L.py[i] - q.py, L.px[i] - q.px) - sg * Math.acos(Math.max(-1, Math.min(1, (r * r + rT * rT - 0.0088) / (2 * r * rT))));
  const mx = q.px + Math.cos(a) * r, my = q.py + Math.sin(a) * r;
  return [mx, my, Math.atan2(sg * (mx - L.px[i]), sg * (L.py[i] - my)), sg, a]; // M, 회전, 휘두르는 쪽, 호 끝 각
};
```

### 1. 기본 도형 6종 (판자 로컬 좌표: 기준점에서 잰 값 · 축은 판자 각 a를 따름 · 새 판은 a = 0)
| 기호 | 이름 | 매개변수(u 정수) | SDF (p = (x, y), 조각 중심 기준) | 쓰는 곳 |
|---|---|---|---|---|
| B | 둥근 네모 | x y hx hy r [deg] | q = (\|x\|−hx+r, \|y\|−hy+r) → hypot(max(qx,0), max(qy,0)) + min(max(qx,qy),0) − r (지금 `sdf`) | 몸통·벽·짐칸·창 |
| O | 원 | x y r | hypot(x, y) − r | 바퀴·머리·혹·도토리·아치 윗부분 |
| C | 캡슐 | x1 y1 x2 y2 t | h = clamp(((p−a)·(b−a))/\|b−a\|², 0, 1) → \|p − a − h(b−a)\| − t (지금 `bar`와 같은 모양) | 다리·목·돛대·레일·날개 |
| E | 타원 | x y a b [deg] | k0 = hypot(x/a, y/b), k1 = hypot(x/a², y/b²) → k0(k0−1)/max(k1, 1e−9). 외곽 근처에서 정확. **1 ≤ a/b ≤ 1.6** | 둥근 몸(양·고래·펭귄)·돛 배부름·잎 |
| W | 쐐기(굵기가 변하는 캡슐) | x1 y1 r1 x2 y2 r2 | 아래 식. \|r1−r2\| < 길이 | 뿔·꼬리 끝·잎 끝·부리·원뿔 코·첨탑 |
| P | 둥근 다각형 | r x1 y1 x2 y2 … (볼록 3~5점) | (안이면 −1, 밖이면 1) × min_i 선분거리(p, v_i v_i+1) − r. 점은 뼈대이고, 보이는 외곽은 뼈대를 r만큼 부풀린 것이다 | 지붕·깃발·돛·삼각 모자·사다리꼴·등 가시 |
```
W: L=|b−a|, u=(b−a)/L, x=|cross(u,p−a)|, y=dot(u,p−a), s=(r1−r2)/L, c=√(1−s²), k=c·y−s·x
   k<0 → hypot(x,y)−r1 ; k>c·L → hypot(x,y−L)−r2 ; 그 밖 → c·x+s·y−r1
```
- **그리기는 세 가지로 끝난다.** ① arc: O. ② ellipse: E(회전은 인자로). ③ 꼭짓점마다 arc(v, r, 앞 변 바깥 법선각, 뒷 변 법선각)를 이으면 선은 저절로 이어진다: P. B는 꼭짓점 4개를 (hx−r, hy−r)로 둔 P다. W(와 C)는 θ = a→b 방향, φ = asin((r1−r2)/L)로 그린다: arc(a, r1, θ+π/2+φ, θ+3π/2−φ) → arc(b, r2, θ−π/2−φ, θ+π/2+φ) → closePath.
- **서브패스는 모두 시계 방향**으로 그린다(P는 읽을 때 넓이 부호로 맞춘다). 방향이 섞이면 nonzero 채움에서 겹친 곳이 구멍이 된다.
- P의 r은 0.004 이상으로 한다. 뾰족한 끝은 3배 축소하면 사라지고 손가락에도 거슬린다.

### 2. 합집합 규칙
- **몸통 SDF = 조각 SDF의 min.** 판자당 조각은 **≤ 4개(본체 포함)**, 권장 2~3개다. 판 하나의 덧조각 합은 판자 수 × 1.5 이하로 한다(gzip 때문).
- **섬 금지**: 각 조각은 앞 조각 하나와 0.010 이상 겹친다. 자기 넓이의 60% 넘게 겹치는 조각은 안 보이므로 뺀다.
- **최소 크기**: O r ≥ 0.012 · C/W 굵기 ≥ 0.010(W 끝 r2는 ≥ 0.006) · P 변 ≥ 0.02. 3배 축소에서 1.5px 밑으로 사라지지 않게 하려는 값이다.
- **무게중심(새 판 = 플래그 켠 판만)**: 판자 로컬 AABB를 0.005 격자로 훑어, 칸 가운데의 min SDF < 0인 칸을 넓이 1로 세서 평균을 낸다. 판 표를 읽을 때 판자마다 한 번만 한다(칠과 무관해서 캐시). 기준점을 그 무게중심으로 옮기고 조각 좌표를 그만큼 뺀다. hx·hy는 합집합의 로컬 AABB 반폭으로 다시 쓴다. 🪵 와르르 폭 `ex`와 덜컹 소리가 그림과 맞게 된다.
- **M1′ 판(플래그 없음)**: Src의 cx·cy·a·hx·hy·rr은 그대로 둔다. 무게중심도 와르르 폭도 그대로다. 덧조각은 cov·hid·그림에만 들어간다. 대신 '보이는 무게중심' 오차를 막는다. 판자의 나사마다 (보이는 무게중심 − 나사) 방향과 (Src 중심 − 나사) 방향의 차가 **≤ 12°**여야 한다. 넘으면 맞은편에 균형 조각을 붙인다. 판자 축을 따라서만 무게중심이 옮겨지면 0°다(굴뚝·부스터).
- **그리기 순서** (판자마다 Path2D 하나에 서브패스를 합치고, 폭 w가 바뀔 때만 다시 만든다)
  1. 그림자 채움(어긋나게)
  2. 옆면 채움(어긋나게, 어둡게)
  3. **테두리: 같은 경로를 2배 굵기(2.4px)로 stroke**
  4. 빛: 같은 경로를 mix(tone, #fff, .35)로 채움
  5. clip(경로) 안에서 (+1.2, +1.2)px 밀어 앞면 그라데이션을 채움
  6. 나뭇결·deco
  - 3·5 덕분에 안쪽 반 테두리와 이음매는 앞면이 덮는다. 지금의 안쪽 roundRect 빛과 마지막 stroke를 이 순서가 대신한다.
- **점선 외곽**(유령·막힘 빨강·📌 ⚠, 드물게 그림): 조각 j마다 다른 조각 i의 '바깥'으로 clip을 겹친다(rect + 조각 i, evenodd). 그 안에서 j를 stroke한다. 이렇게 하면 이음매 점선이 없다. 1504줄의 roundRect 직접 호출도 plankPath로 바꾼다.
- **성능**: 서브패스는 판자 12 × 조각 4 = 48개 이하다. 그리기 횟수는 판자당 5번으로 지금과 같다. clip은 점선 외곽을 그릴 때만 쓴다.

### 3. 판마다 ≥ 2종 · 실루엣 읽힘 기준
- **새 판**
  - 조각 종류(B O C E W P)를 ≥ 2종 쓴다.
  - 둥근 네모만으로 된 판은 0이다.
  - 조각 ≥ 2개인 판자가 ≥ 1개 있다.
  - E·W·P 중 하나 이상을 쓴다.
- **장난감 특징 부위 ≥ 1개는 둥근 네모가 아닌 조각**으로 만든다. 예: 뿔·돛·깔때기·첨탑·지느러미·등 가시.
- **읽힘 시험**: 나사와 deco 없이 판자 합집합만 회색으로 칠한 쉬는 자세를 **1/3 크기**(판 폭 121px)로 찍는다(`shots/sil-<판>.png`). 📐와 🧪가 이름표 없이 장난감 이름을 맞히면 통과한다. 판 선택 칸은 1/6 크기라 이모지를 같이 둔다.
- **같은 실루엣**: 두 판의 쉬는 자세 전체 합집합 IoU(0.01 격자)가 ≥ 0.7이면 같은 실루엣으로 본다. gate가 틀 판과 비교한다(변형판 규칙의 '실루엣이 다르다').

### 4. 나사 자리 둘레 여백 (그림 = 판정)
- 판정은 `sd < COVER(0.021)`이면 막힘, `sd < HIDE(−0.026)`이면 아예 안 보임(유리는 숨김 0)이다. 나사 머리 반지름은 SR 0.032다.
- **자기 나사**: 나사를 품는 **조각 하나**만으로 깊이 ≥ **0.030(6u)**여야 한다. 머리가 판자 밖으로 나가는 것이 0.002 이하가 된다. 두 조각에 걸친 나사와 오목한 홈(두 조각이 만나는 안쪽 모서리)에서 0.05 안의 나사는 금지한다.
  - M1′ 최소는 0.019(1판 꼬리, 막대 t 0.022)다. 지문이라 그대로 둔다. 새 판은 막대 굵기 ≥ 0.030이다.
- **아래 판자 나사**: 이 판자의 모든 자세(쉼 · 나사마다 매달림 · 못)에서 **sd ≤ 0.012(확실히 덮음: 머리 60% 이상 가림) 또는 sd ≥ 0.040(확실히 안 덮음: 틈 3px)**이어야 한다.
  - 0.012 < sd < 0.040은 **회색 띠**로 금지한다. COVER가 그 한가운데라 눈으로는 덮였는지 모른다.
  - M1′에는 지금 55곳(자세 × 나사)이 있다(1판부터 2 · 2 · 2 · 4 · 9 · 13 · 11 · 12). 지문이라 그대로 두고, 새 판 gate는 0을 요구한다.
- **이음매 밑 금지**: min식은 합집합 안쪽 깊이를 얕게 본다. 그래서 이음매 근처에서는 숨김을 덜 잡는다. 아래 판자 나사를 이음매 0.03 안에 두지 않는다.
- **망치 판자**: 망치 머리가 붙는 가장자리(hamEdge = 본체 조각의 변) ±0.07에는 덧붙이지 않는다. **통나무**는 M1′에서 폭을 바꾸지 않는다.

- 위 띠~작업대(y 0~1.245)는 그대로 둔다. 시뮬 좌표 · 연출 · 실패 카드 자리가 같다.
- 남는 E = A − 1.45는 아래로 준다.

### 7. 이름 · 닮지 않기
- 장난감 이름과 판 자리는 📐 표(CONTENT 'M2 30판 표 v0')를 따른다. 🎨는 모양 문법만 정한다. 위 와이어의 1-4 🐿️은 v0 표의 예다.
- 모든 판자는 **나무 장난감 판자**다(나뭇결 · 둥근 모서리 · 원색 칠).
  - 금속 판 · 볼트 질감 · 드릴 아이콘은 쓰지 않는다(ART v1).
  - 실존 나사 게임의 판 모양과 색 조합을 따라 하지 않는다.
- 동물은 기하 조각을 합쳐서만 만든다. **큰 원 위에 작은 원 둘(귀)인 머리 같은 유명 캐릭터 실루엣 조합은 금지**다. 동물 귀는 W나 P로 만든다.

### 8. gzip 예산 (지금 39.2KB · M2 상한 52 · 목표 50)
- 판 표에는 판자마다 덧조각을 문자열 한 칸으로 붙인다. 예: `'W -6 -9 2 -7 -18 3;W 0 -9 2 1 -18 3'`(36자).
  - 판 한 줄에 **+약 50B(gzip)**가 붙는다(무작위 22판 × 판자 3 × 조각 1~3으로 재면 48B/판).
  - 새 22판 ≈ +1.1KB, M1′ 8판 덧조각 25개 ≈ +0.25KB다.
- 엔진: SDF 6종 · 경로 · 무게중심 · 읽기 약 40줄 ≈ +1.1KB.
- 합계 약 **+2.4KB**. 📋 '새 판 0.25KB/판'에 판당 약 0.05가 붙는다. 넘치면 덧조각을 '판자당 평균 ≤ 1개'로 줄인다.
