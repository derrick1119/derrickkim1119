  2. 같은 판을 두 번째 할 때 첫 판과 다른 방법으로도 깰 수 있다(정답이 하나로 정해진 느낌이 없다).
  3. 월드 마지막 큰 판에서 "아, 앞에서 배운 걸 섞는구나"가 느껴지고, 두세 번 안에 깬다.
  4. 3★ 못 받은 판에 돌아가 다시 해 보고 싶어진다.

## M3 아트·사운드 상용 품질: 작은 욕조 세계 (7사이클, 한도 10)
**왜 이 순서**: 판 요소가 M2에서 다 정해졌으니 캐릭터 시트·팔레트·UI를 한 번에 통일할 수 있다(기준 9).
- **포함**: 디자이너 ART.md 확정(팔레트·캐릭터 시트: 오리·황금 오리·엄마 오리·고양이·고무 상어·배) · 캔버스 디오라마(민트 타일, 법랑 욕조, 물 굴절 빛, 김 서림) · juice(물방울 파티클·화면 흔들림·떠오르는 글자) · UI 스타일(버튼·별·판 선택) · 효과음 WebAudio 합성(찰박·꽥·쏙·냐앗·별)과 짧은 배경 루프, 소리 끄기 · 진동(지원 기기만) · 월드별 색 변주.
- **제외**: 외부 이미지·폰트·음원 파일 복사(직접 만든 것만), 새 판·새 규칙.
- **완료 기준(기계)**: 390px·데스크톱 스크린샷이 월드마다 있음(제목·판 선택·플레이·클리어) · Playwright 4× CPU 저속에서 프레임 중앙값 ≤ 16.7ms, 95% ≤ 33ms · 텍스트 대비 ≥ 4.5:1 · 소리 끔 설정 저장 테스트 · gzip ≤ 45KB · funqa 수치 M2 대비 퇴행 없음(±5%).
- **오너 테스트 허들**
  1. 첫 화면 스크린샷을 남에게 보여 줘도 "이거 스토어 게임이야?"라는 말을 들을 것 같다.
  2. 소리를 켜고 화면을 안 보고도 찰박·꽥·쏙(둥지)·꿀꺽(상어)이 구별된다.
  3. 오리가 둥지에 들 때, 판을 깰 때마다 작은 축하가 손에 느껴진다(파티클·흔들림·진동).
  4. 휴대폰에서 버벅임 없이 매끄럽게 돈다.

## M4 메타·저장·보상: 내일 다시 올 이유 (6사이클, 한도 9)
**왜 이 순서**: 해금할 판(M2)과 보여 줄 아트(M3)가 있어야 보상이 의미 있다.
- **포함**: 기획자 경제 설계(GDD 경제 절) · 별로 월드 열기 · 오리 수집(황금 오리·별로 꾸미기 오리를 열고, 욕조에 띄워 보기) · **오늘의 목욕**(날짜 시드로 결정적인 데일리 판, 스포일러 없는 공유 텍스트) · 저장 데이터 버전·이전 · 설정(소리·진동·움직임 줄이기).
- **제외**: 실제 결제·광고·계정·서버.
- **완료 기준(기계)**: 저장 왕복·버전 이전·저장 불가 환경 테스트 · 같은 날 같은 데일리 판 테스트 · 경제 시뮬레이션: 캐주얼 봇이 30판 진행 중 별 부족으로 막히는 일 0, 수집품 70% 해금 ≈ 2~3시간 플레이 · 공유 텍스트에 판 해법 정보 0(테스트) · gzip ≤ 50KB.
- **오너 테스트 허들**
  1. 앱을 닫았다 다시 열어도 별·열린 판·모은 오리가 그대로다.
  2. 판 선택 화면에서 "별 몇 개 더 모으면 다음 월드"가 보이고 그걸 노리게 된다.
  3. 오늘의 목욕을 하고 결과를 공유 문구로 복사하면 친구에게 보내고 싶은 모양이다(답은 안 보임).
  4. 새 오리를 열어 욕조에 띄워 보는 게 작은 보상으로 느껴진다.

## M5 출시 준비: 졸업 (5사이클, 한도 8)
- **포함**: 성능(첫 로드 → 첫 톡 가능 ≤ 1.5초) · 접근성(색 둥지에 무늬도 함께 → 색약 구분, 움직임 줄이기, 키보드만 30판, 화면 낭독용 이름) · **수익화 설계 화면**(GDD 안: 광고 보고 힌트·오리 팩 같은 목업만, 실제 연동·결제 없음, 강요 없는 흐름) · 설정·크레딧·개인정보 문구 · 홈 화면 추가(manifest·아이콘) · 출시 체크 E2E.
- **완료 기준(기계)**: E2E가 30판 자동 플레이 + 데일리 + 저장 불가 환경에서 콘솔 에러 0 · 첫 톡 가능 ≤ 1.5초(저속 프로필) · 키보드만 1월드 완주 테스트 · 색 없이(흑백 필터) 둥지 구분 스크린샷 · gzip ≤ 55KB · 모든 FUN 기준 통과(❌ 0) · QC 체크리스트 전부.
- **오너 테스트 허들**
  1. 처음 보는 사람(가족·친구)에게 아무 말 없이 건네도 30초 안에 규칙을 알고 5분 넘게 한다.
  2. 수익화 화면(힌트·오리 팩)이 있어도 억지스럽지 않고 "이 정도면 돈 낼 수도"가 든다.
  3. 30판 + 데일리를 하는 동안 깨짐·멈춤·이상한 화면이 하나도 없다.
  4. "이대로 스토어에 올려도 되겠다"고 말할 수 있다 → **졸업**.

## 일정 규칙
1. 마일스톤이 150% 한도에 닿으면 PM이 범위를 줄인다(완료 기준과 무관한 항목을 다음으로 넘긴다). 완료 기준은 낮추지 않는다.
2. 한 작업이 2사이클 연속 끝나지 않으면 PM이 반으로 쪼갠다.
3. FUN 지표 목표 개정은 FUN QA 근거와 TALK 기록이 있어야 하고, 코드보다 먼저 커밋하며, 오너 테스트 요청 때 밝힌다. 통과시키려고 목표를 옮기는 것은 금지다.
4. 완료 기준을 다 넘으면 남은 체크박스와 상관없이 QC로 간다. 남은 항목은 다음으로 넘긴다.
5. '오너 테스트 대기' 중에는 새 기능을 만들지 않는다. 사이클은 한 줄 보고로 끝낸다.
6. 매 사이클 PM은 "지금" 표(진척 %, 다음 오너 테스트 시각 UTC/KST)를 다시 계산한다.

## 재수립 규칙: 오너 피드백을 받으면
- **R1 그대로 적는다**: 오너의 말을 원문 그대로 STATUS와 TALK 맨 위(💬)에 적는다. 해석은 그 아래에 한다.
- **R2 피드백 사이클(F01, F02)**: 다음 사이클은 피드백이 최우선이다. 최대 2사이클이고 마일스톤 일정 밖에서 센다. 각 F 사이클은 ① 오너의 말을 숫자로 먼저 잰다(예: "어렵다" → 그 판의 캐주얼 클리어율·실패 이유) ② 고칠 것과 폐기 기준을 정한 뒤 고친다.
- **R3 마디별로 나눈다**: 오너의 말 한 마디마다 (a) 이번 허들 미달이면 이번 마일스톤에서 고친다 (b) 뒤 마일스톤 범위면 그 마일스톤으로 옮기고 이유를 쓴다 (c) 지표가 못 잡은 것이면 FUN 기준을 새로 만들거나 고친다(코드보다 먼저). 오너의 말은 재미의 유일한 진짜 측정값이다.
- **R4 마일스톤을 다시 쓴다**: 이 문서의 해당 마일스톤에 "재수립 N차" 절을 더한다(무엇이 미달 → 무엇을 어떻게 → 새 완료 기준·허들 → 다시 테스트할 예상 시각). 허들 문구는 오너의 말을 뒤집은 문장으로 바꾼다. 뒤 마일스톤의 범위·사이클·한도도 다시 계산한다.
- **R5 다시 요청한다**: 피드백을 반영하고 QC를 다시 통과하면 같은 마일스톤 테스트를 한 번 더 요청한다. F02 뒤에도 미달이면 마일스톤을 둘로 쪼개 먼저 고칠 절반만 다시 테스트받는다.
- **R6 통과**: 오너가 "통과"·"다음"이라고 하면 ✅로 바꾸고 다음 마일스톤을 시작한다. 부분 통과면 통과한 허들은 ✅, 남은 것은 R3으로 처리한다.
