## v0.3 (D007, M2 설계): 욕실 3 × 10판
> 📐 기획 · 2026-11-13 · D007. 이 표가 정하는 것은 **판의 질문, 기믹, 순서, 목표 시간**이다. 좌표·톡·par는 각 판을 만드는 사이클에 ✏️가 넣고 funqa로 재서 맞춘다('첫 값'은 출발점일 뿐).
> 근거: funqa-d006-final(n=100), FUN v1.5, MILESTONES M2, GDD §4. 실험 하나(scratchpad/plan7/wall.ts, 3분): **벽에 붙은 오리(x 0.05)를 열린 쪽 0.10~0.30에서 치면 오리가 벽에서 떨어져 친 쪽으로 0.25~0.35 튀어나온다.** 벽에서 떨어져 있으면(0.30) 0.40에서 칠 때 바깥으로 0.16 밀린다 — '벽 물결'은 지금 물리만으로 **반대 동사(끌어온다)**. 1-7을 새것으로 세운 근거.

### 3. 숙련 천장: 🏅 고수 메달

1. 배우는 봇에 판을 넘어 원리를 가져가는 학습 모델이 없다 → 4판이 가르쳤는지 대리 지표로 '가운데 톡 → 0마리 · par 불가'와 '★톡: 캐주얼 0.70 vs 무작위 0.14'.
2. C4 par ≥ 2 정의는 소개 판에서 구조적으로 50~70% — 목표 범위 재정의.
3. E6와 E1·E2 중 어느 쪽을 먼저 지킬지.

## 0. 공통 규칙 바꾸기: 쏙·꿀꺽 = 톡 1개 잃고 수도꼭지에서 "뿅!"
| 항목 | 규칙 (코드) | 왜 |
|---|---|---|
| 대상 | 배수구에 빨린 **오리·황금 오리·배**, 상어에게 먹힌 **오리·황금 오리**. 상어가 빨리면 지금처럼 사라지고 벌은 없다("상어도 쏙!") | 모든 오리에 예외 없는 한 규칙이어야 읽힌다. 상어가 빨리는 건 상이다 |
| 재등장 위치 | `FAUCET = {x: 0.5, y: 0.06}`(그린 수도꼭지 바로 앞), `vx = vy = 0`, `st = FREE`, `hitT = -99`, `hitR = -1`, `stun = 0` | 오리가 "어디서 다시 나오지?"를 매번 같은 곳에서 본다 |
| 겹침 예외 | 아래 중 하나라도 맞으면 수도꼭지 대신 **그 오리의 판 시작 자리**(`mk`에 `sx, sy` 저장, 뒤집기·흔들기 뒤 값)로 보낸다: ① 맞는 둥지와 거리 < `n.r + NEST_TOUCH + RAD[k]` ② 배수구와 거리 < `dr.pr` ③ 물줄기 네모 안 | ① 공짜 입성, ② 다시 쏙(무한 반복), ③ 공짜 운반(7판)을 막는다 |
| 시뮬레이션 | 순간이동은 즉시 한다(`phys` 안). `Sim.pen++`로 세고 `clone`에도 복사한다. 미리 보기·봇도 같은 규칙으로 돈다 | 결정성이 유지되고 미리 보기 점선이 "뿅"까지 보여 준다 |
| 톡 벌 | `step`에서 `phys` 직후 `k = s.pen − s.penA`가 0보다 크면 `taps = max(0, taps − k)`, `used += k`, `lastTap = s.t`, `penA = s.pen`. `newStage`에서 `pen = penA = 0` | 잃은 톡도 쓴 톡으로 센다. 그래야 ★2(톡 N번 이하)에 배수구가 의미가 있다. `lastTap`을 갱신하면 실패 판정이 0.5초 늦어져 "뿅"을 볼 시간이 생긴다 |
| 톡이 0일 때 | 0 밑으로 내려가지 않는다(`used`는 +1). 특별 처리는 없다. 물결이 남아 나머지 오리가 들어가면 **클리어**, 잔잔해지면 기존 판정대로 실패 "톡을 다 썼어요" | 실패 이유를 하나로 모으고(GDD §5.3), 남은 물결로 뒤집는 짜릿함은 남긴다 |
| 황금 오리와 ★3 | 황금 오리도 재등장하고 톡 1개를 잃는다. ★3 판정은 지금 그대로(클리어 순간 `gold.st >= 0`)다. 빨려도 다시 넣으면 ★3 가능. `goldLost`는 쏙에서 더 이상 켜지 않는다 | ★3이 한 번의 실수로 영영 막히면 그 판을 다시 할 이유가 줄어든다. 대가는 톡 1개와 ★2 위험이다 |
| 결과 카드 | 실패 머리글은 "톡을 다 썼어요" 하나. 아랫줄에 `쏙 ×a · 꿀꺽 ×b`(0이면 생략). 연출 사건: 빨린 자리 `suck` "쭈욱… 쏙!" → 수도꼭지 `pop` "뿅! 톡 −1" | 실패 이유는 하나로 두되 *왜* 톡이 모자랐는지는 보이게 한다(기준 8) |
| 봇 | `value()`: `v -= S.pen * 700`, 다 넣은 경우 `100000 − S.pen * 30000 + …`. 캐주얼·무작위 봇은 그대로 | 숙련 봇이 공짜 쏙을 해법으로 쓰지 않게 한다 |
| FUN 지표 | N4("톡을 다 썼어요" ≤ 50%)는 이유를 하나로 모으면 늘 100%가 된다. 🧪에게 "실패한 판 중 쏙·꿀꺽이 1번 이상 있었던 비율"로 재정의를 요청한다(코드보다 먼저) | 지표가 바뀐 규칙을 못 잡는다 |
| 효과 | 3판 현행 배치에 재등장 규칙만 켜면 처음 봇 첫 시도 0.20 → 0.17로 사실상 같다. **규칙만으로는 3판이 안 풀리고 배치 재설계가 필요하다**(§1의 3판) | 오너 기준 7은 규칙이 지키고, 막힘은 배치가 푼다 |

## 1. 판 1~4 (M1에서 손볼 판)
### 판 1 · 넓은 둥지 (온보딩)
- 질문: **"가운데를 톡! 한 번에 몇 마리?"**
- 오리 `[[0.5,0.42,0],[0.62,0.6,0],[0.38,0.6,0]]` · 황금 `[0.5,0.78]` · 둥지 8개 그대로 → *왜*: 첫 톡에 첫 3초 안 둥지 입성 중앙 2마리가 이미 나온다(M1 기준 ≥ 2 충족).
- **taps 9 → 12**, par 1 그대로 → *왜*: 처음 봇 첫 시도 0.94 → 0.99(100번). M1 기준 ≥ 0.95. 1-1은 "사실상 못 진다"(GDD §8).
- 측정(바꾼 뒤): 처음 0.99 / 다시 포함 1.00 · 처음 별 1.89 · 숙련 3.0. 처음 별이 1.6을 넘는 건 온보딩 판이라 허용한다.

### 판 2 · 거품 섬 (미리 보기를 가르치는 판)
- 질문: **"섬 뒤에 숨은 오리까지, 두 번에 다!"**
- 오리·황금·섬 `[0.5,0.6,0.1]` 그대로. 둥지는 큰 4개 r **0.15 → 0.16**, 구석 4개 r **0.13 그대로**: `[[0.5,0.1,0.16,-1],[0.9,0.6,0.16,-1],[0.1,0.6,0.16,-1],[0.5,1.1,0.16,-1],[0.1,0.1,0.13,-1,0,1],[0.9,0.1,0.13,-1,0,1],[0.1,1.1,0.13,-1,0,1],[0.9,1.1,0.13,-1,0,1]]`
- **taps 8 → 10**, par 2 그대로 → *왜*: 처음 첫 시도 0.64 → 0.85(M1 기준 ≥ 0.8). 섬 그늘 질문은 그대로 두고 여유만 늘린다.

### 판 3 · 배수구 소개 (전면 재설계)
- 질문: **"배수구 바로 옆을 톡 — 오리가 밖으로 튕겨 나가요!"**
- 배수구 `[0.5,0.6]` · **오버라이드 `pullR: 0.12`(기본 0.17), `pull: 0.00012`(기본 0.0002)** → *왜*: 끌림 면적이 50%가 되고 가장자리에서 미끄러지는 게 느려진다. 오리 시작 거리(0.18~0.24)가 끌림 밖이라 가만두면 빨리지 않는다.
- 오리 `[[0.5,0.42,0],[0.34,0.72,0],[0.66,0.72,0]]` · 황금 `[0.5,0.84]` → *왜*: 배수구를 셋이 둘러싼다. 배수구를 치면 아래 둘은 아래 구석 둥지에 쏙 들고("와, 밖으로!"), 위 오리는 (0.5, 0.14)에서 멈춰 한 번 더 쳐야 한다(par 2). 바깥(0.5, 0.3)을 치면 위 오리가 빨려 수도꼭지에서 뿅 → 규칙이 몸으로 읽힌다.
- 둥지 `[[0.12,0.14,0.17,-1],[0.88,0.14,0.17,-1],[0.12,1.06,0.17,-1],[0.88,1.06,0.17,-1],[0.1,0.6,0.14,-1,0,1],[0.9,0.6,0.14,-1,0,1]]` → *왜*: 뒤 가운데 둥지는 일부러 비운다. 수도꼭지 재등장 자리와 겹치면 공짜 입성이 되기 때문이다. 옆 둥지 2개는 소개 판의 여유다.
- **taps 10**, **par 2** → *왜*: 숙련 봇은 톡 2번이면 깬다. 톡이 8개일 때는 처음 봇 다시 포함 0.78이고 10개일 때 1.00이다.
- 측정: 처음 첫 시도 **0.20 → 0.80** / 다시 포함 **1.00**(M1 기준 ≥ 0.7) · 처음 별 1.68 · 쏙 0.66회/판(배수구가 여전히 느껴짐) · 캐주얼 1.00, 별 2.49 · 숙련 1.00, 별 3.0.
- 화면: 끌림 원은 반지름 `dr.pr`로 그린다. 둘레 물빛으로 "여기 쳐 봐"를 유도한다(GDD §13-3).

### 판 4 · 색깔 둥지 소개 (오리 2마리로 줄임)
- 질문: **"가운데를 톡 — 노랑은 노랑 쪽, 분홍은 분홍 쪽으로!"**

- 둥지 `[[0.12,0.6,0.2,0],[0.88,0.6,0.2,1],[0.12,0.12,0.15,0,0,1],[0.88,0.12,0.15,1,0,1],[0.12,1.08,0.15,0,0,1],[0.88,1.08,0.15,1,0,1]]` → *왜*: "왼쪽 벽은 전부 노랑, 오른쪽 벽은 전부 분홍"으로 한눈에 읽힌다. 2개짜리 색 둥지일 때 처음 봇 첫 시도는 0.38이었다.

## 2. 코드 반영 목록 (개발용)
1. `StageDef`에 `pullR?: number; pull?: number;`를 넣는다. `Layout.drains`는 `{x, y, r, pr, pw}`(`pr = d.pullR ?? PULL_R`, `pw = d.pull ?? PULL`)로 바꾼다.
2. `PULL_R`와 `PULL`을 읽는 곳을 전부 `dr.pr`, `dr.pw`로 바꾼다. 대상은 `phys` 끌림, `cosmetic` 겁먹은 표정, `value` 위험, `drawAll` 끌림 원 2곳이다.
3. `Obj`에 `sx, sy`, `Sim`에 `pen`, `DuckState`에 `penA`, 표시용 `sucks`·`chomps`를 넣는다. `respawn(S, o)`는 §0의 규칙대로 만든다. `SUCKED`·`EATEN`은 상어용으로만 남긴다.
4. STAGES 1~4를 §1의 값으로 바꾼다. 판 시작 카드 질문 문장은 `StageDef.ask`에 둔다(GDD §13-8, M1이면 같이).
5. 테스트: 쏙 → 톡 −1 · `used` +1 · 수도꼭지 재등장 / 겹침 예외 → 시작 자리 / 톡 0에서 쏙 → 0 유지 / 결정성 / 숙련 봇 1~8판 클리어 1.0 유지.
