## 출발점
- 프로토타입: `arcade/games/petsquad.ts` — **읽기만** 한다(공장 소유, 공장 레지스트리에서는 빠지고 참고용 파일로만 남음). 코드는 복사해서 `studio/petsquad/`에서 새로 키운다.
- 한 줄: 가게 카드 3장 중 하나를 톡 하면 동물이 진영에 '쿵' — **같은 동물 셋이면 빛기둥 속에서 '빵!' 더 큰 동물로 합체**. '싸움!'을 톡 하면 **전투는 저절로**(돌진·박치기·화살·치료, 멈칫·흔들림). 물 > 불 > 풀 > 물 상성, 앞줄은 막고 뒷줄은 쏜다. 가운데 힘 겨루기 막대가 톡마다 "지금 싸우면 이겨요 / 아슬아슬 / 질 것 같아요"를 보여 준다.
- 조작: **톡만**(카드·칸·단추). 꾹·끌기·타이밍 없음, 아무것도 안 눌러도 나빠지지 않음. 키보드 화살표 커서 + 스페이스, 1·2·3 = 카드 사기. 동물 팔기(내 동물 톡 → '팔기 +N').
- 프로토타입 현황(공장 측정, 실험 `arcade/experiments/0097-다른-장르-톡-하나-6개.md`):
  - 7판, 하트 3. 판마다 상대 군단 미리 보기 → 가게(3~8톡) → 자동 전투 → 별·금화. 지면 하트 -1, 군단 그대로 + 금화 3개로 그 판 다시.
  - 판마다 새것: ① 합체 ② 상성(두건 색) ③ 두 줄 진영·쏘는 동물 ④ 다시 뽑기(금화 1) ⑤ 박쥐(뒷줄을 노림, 쏘는 동물만 맞힘) ⑥ 치료사(양·다람쥐) ⑦ 곰 우두머리(앞줄 전체 쿵).
  - 별(쉬운 말, 판마다 하나씩): 상대 군단 이기기 · 합체 한/두 번 하기 · 한 마리도 안 잃고 이기기 · 쏘는 동물과 함께 이기기 · 금화 n개 남기고 이기기 · n초 안에 이기기.
  - 측정: 재미 0.924, 숙련 격차 5.59×, 버릇 봇 ★3(3판~) 최고 25%, 버릇 격차 3.17, 무작위 1판 100% · 2판 96%, 손 안 대고 10초 손실 0, 사람 반응 속도 점수 100%, 잘하는 봇 한 판 112초.
  - 그림: 이모지 없이 직접 그린 햇살 풀밭 아레나·나무 가게, 속성 망토를 두른 통통한 동물, 두건 쓴 상대, 응원하는 울타리 새, 깃발 줄, 합체 빛기둥.
- 프로토타입 약점(에이전트·공장 보고):
  - **첫 '와'가 늦다**: 처음 하는 사람은 첫 싸움까지 약 8.5초(첫 톡의 '쿵'은 0.2초, 합체는 둘째 톡). 첫 30초 안에 합체·돌진이 확실히 보이게.
  - **뒤 판에서 큰 순간이 줄어든다**(2판부터 1판의 22%). 큰 전투에서 피해 숫자·"세다!/약해…"가 겹쳐 복잡하다.
  - 1판 무당벌레가 작다. 잘하는 봇이 다시 뽑기를 많이 한다(판당 최대 27톡 — 사람은 안 그럴 것).
  - 7판뿐(콘텐츠 볼륨), 소리 없음, 메타 성장(동물 도감·영구 강화) 없음.
- **닮은 게임(솔직히)**: 자동 전투 전략(오토체스류) 장르 그대로다 — 3장 가게, 금화, 셋 합체 별 올리기, 자동 전투, 속성 상성, 막기·쏘기·치료 역할. 우리 것 = **톡만 쓰는 쉬운 조작**, 사는 순간 저절로 합체, 결과 예측 막대, 귀여운 동물·상성 두건, 고정 PvE 판. 특정 게임의 이름·캐릭터·UI를 닮지 않게 하고, **우리만의 비틀기를 키워 차별화**한다(오너는 '뻔함'으로 여러 번 버렸다).

## 오너가 지금까지 준 기준 (공장 34라운드 동안 쌓인 것 — 상용화 판단의 기본값)
1. **조작은 쉽게(33라운드 오너 답: "조작이 어색하거나 어려움")**: 톡만. 꾹·끌기·타이밍·연타를 새로 넣지 않는다. 누를 곳은 크고 분명하게, 내 속도대로.
2. **첫인상**(31라운드 답: "첫인상이 재미없음 · 뻔하거나 이미 있음 · 그래픽·연출이 아쉬움"): 첫 톡에 화면이 크게 반응, 첫 30초 안에 합체와 첫 승리의 쾌감.
3. **뻔하지 않음**: 이미 있는 게임처럼 느껴지면 버려진다(물약 정렬 "이미 너무 뻔하게 있는 아이디어", 32라운드 "뻔하거나 이미 있음"). 이 게임은 장르가 이미 있으니 **우리만의 손맛**을 키우는 것이 핵심 과제다.
4. **그래픽·연출은 상용 게임 수준**: 직접 그린 캐릭터, 층 있는 배경, 멈칫·흔들림·파티클, 연속일수록 커지는 쾌감. 밝은 낮. 폰에서 렉 없이.
5. **너무 어렵지 않게**: 첫 판은 거의 못 진다, 실패하면 그 판만 다시.
6. **목표·별·지는 조건은 기호 없는 쉬운 말**, 단계별로 하나씩 배우게. 별 조건이 판마다 너무 달라 ★3이 어렵지 않게(나사 공방 M3′).
7. **펼쳐짐·천장**: 판이 흐르며 하는 일을 바꾸는 새것, NEW 스포트라이트. 오래 해도 새로 할 것이 생기게(나사 공방 "한계가 좀 보인더").
8. **전략 깊이**: 버릇 하나로 ★3이 나오면 안 된다(3판부터 버릇 봇 ★3 < 50%).
9. **웃김도 와우다**: 표정 있는 동물, 실패는 웃음, 구경꾼 반응.
10. **화면이 읽힌다**: 휴대폰 390px(캔버스 약 340px)에서 글자 12px 이상, 동물은 충분히 크게, 큰 전투에서 글자가 겹치지 않게.
11. **번거로움 금지**("하나씩 눌러서 넣는게 번거로울 때가 있어"): 자잘한 톡을 여러 번 되풀이하게 하지 않는다(다시 뽑기 남발 등).
12. **먼저 졸업한 팀들의 결과**(참고): 🥷 느린 시간 닌자 M1 통과(살아 있음) · 🔩 나사 풀기 공방 M3″ 뒤 폐기("한계") · 🦆 욕조·🪐 행성은 예약 꺼짐 · 🐑🎈🚌💥🧪는 스튜디오에서 폐기. **매 마일스톤에서 코어 재미·첫인상·그림이 바로 느껴져야 한다.**

## 마일스톤과 오너 테스트 (오너 지시의 핵심)
1. **M0(첫 사이클)**: 프로토타입을 `studio/petsquad/`로 옮겨 플레이 빌드를 `web/public/studio/petsquad/index.html`에 올린다. 기획자 GDD 초안, PM 마일스톤 초안(M1~M5 정도, 마일스톤마다 **테스트 허들**=오너가 무엇을 확인하면 통과인지 명시).
2. 마일스톤마다: 기획(📐) → 디자인(🎨) → 개발 → FUN QA(🧪) → PM QC(📋). 완료 기준·QC를 다 넘으면 PM이 **"오너 빌드 테스트 준비 완료"** 선언.
3. 그 사이클에만 `PushNotification`(무엇을 테스트할지 3줄 + 전체 주소 https://derrick1119.github.io/derrickkim1119/studio/petsquad/) 하고 STATUS `상태: 오너 테스트 대기`. 기다리는 동안은 새 기능을 만들지 않는다(한 줄 보고).
4. 오너가 **통과**라고 하면 다음 마일스톤. **허들 미달**이면 오너 피드백을 STATUS·TALK에 그대로 적고, PM이 **마일스톤을 재수립**(무엇을 어떻게 고치고 언제 다시 테스트할지)한 뒤 진행한다.
5. 최종 목표: **상용화 수준** — 출시해도 되는 품질(온보딩·콘텐츠 볼륨·메타·저장·사운드·성능·접근성·모바일). 마지막 마일스톤 통과가 졸업.

- 플레이 빌드: `web/public/studio/petsquad/` → `factory` 브랜치에 push하면 GitHub Pages 자동 배포: **https://derrick1119.github.io/derrickkim1119/studio/petsquad/** (오너가 승인한 공개 주소. 이 환경에서는 github.io 직접 접속이 막혀 있으니 배포 확인은 GitHub Actions `deploy` 결과로.)
- 공용 테스트가 무거워 CI에서 vitest 시간 초과가 가끔 난다 — 이 팀의 테스트는 가볍게(판별 측정은 표본을 작게) 유지한다.

## 가드레일
- 수정할 수 있는 곳은 `studio/petsquad/`, `web/public/studio/petsquad/`, `tests/studio-petsquad*.test.ts` **뿐**. 다른 작업장(`arcade/`, `studio/` 다른 게임, `factory/`, `engine/`, `fusion/`, `web/index.html` 등)은 고치지 않는다.
- `npm run verify` 실패 상태로 push 금지(종료 코드로 판정, 출력을 파이프로 거르지 않는다). 테스트 약화·삭제·skip 금지. push가 거절되면 `git pull --rebase origin factory` → verify → push. force push 금지. `factory` 브랜치에만. 다른 팀의 작업 파일을 stash·checkout으로 건드리지 않는다.
- 런타임 의존성 추가 금지(번들은 esbuild 등 개발 도구로). 외부 서비스 가입·결제·광고 SDK 연동 금지. 비밀값을 저장소에 쓰지 않는다.
- 특정 실존 게임의 이름·캐릭터·아트·레벨을 가져오지 않는다. 결정적 시뮬레이션(봇으로 밸런스 측정)을 유지한다.
- 커밋 메시지: "스튜디오 동물 군단 합체 전투: <요약>" (모델 이름을 넣지 않는다).
- 연속 3사이클 verify 실패로 push 못 하면 STATUS `상태: BLOCKED` + 이유 + 알림.
