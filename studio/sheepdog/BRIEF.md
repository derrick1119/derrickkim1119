# 스튜디오 브리프 — 🐑 양치기 멍멍 (상용화)

> 게임 발견 공장(`arcade/`) 23라운드에서 오너가 고른 게임(2026-11-12, "1,2,4 아이디어 좋네")을 **상용화 수준의 게임 하나**로 만드는 팀의 작업장.
> 이 세션은 이 게임 하나만 맡는 **팀 전체**를 운영한다. 같은 날 졸업한 다른 두 게임도 각자 별도 세션(팀)이 맡는다.

## 오너의 지시 (2026-11-12, 그대로)
> "따로 세션으로 보내서 개발을 진행하자. 전문 기획자를 붙여서 컨텐츠랑 시스템을 디테일하게 기획해주고, 개발자가 그걸 보고 반영을 해. 그리고 디자이너가 상용화 수준으로 알맞은 컨셉과 퀄리티의 리소스를 제작해. 그리고 fun QA가 계속해서 재미를 검증해줘. 그리고 PM은 마일스톤을 수립한뒤에 각 마일스톤 달성 시마다 나한테 빌드 테스트를 요청해. 마일스톤 테스트 허들을 넘지 못하면 부족한 부분을 피드백줄테니까 마일스톤을 재수립해서 진행해. 최종 목표는 상용화야. 상용화 수준에 맞는 게임을 하나 만드는 팀들을 운영하는거야. 각 아이디어가 각 팀이 되는거지."

## 출발점
- 프로토타입: `arcade/games/sheepdog.ts` — **읽기만** 한다(공장 소유, 공장에서는 레지스트리에서 빠지고 참고용 파일로만 남음). 코드는 복사해서 `studio/sheepdog/`에서 새로 키운다.
- 한 줄: 목장을 톡 하면 강아지가 달려가 "멍!" — 원 안의 양 떼는 반대쪽으로 우르르 달아나고, 까만 양 한 마리는 거꾸로 강아지 쪽으로 온다. 양을 모두 울타리에 넣으면 통과.
- 조작: 톡(누르고 있으면 미리 보기, 떼면 짖기) · 키보드 화살표+스페이스
- 프로토타입 현황: 8판(첫 울타리 → 까만 양 → 개울·다리 → 기절 염소 → 늑대 → 바람 언덕 → 울타리 둘 → 밤). 별 = 다 넣기 · 멍멍 횟수 · 보너스(꽃밭/까만 양). 측정: 재미 0.950, 숙련 격차 5.6×, 무작위 1판 92% · 2판 60%. 약점: 규칙 2줄 밖 보조 규칙 둘(문 앞 흙자리 자동 입장, 아무도 없으면 안 짖음), 6·8판 까만 양 별이 어려움.
- 아트 방향(프로토타입): 해 질 녘 언덕 목장 디오라마 — 노을빛, 뭉게뭉게 양털, 긴 그림자, 나무 울타리, 목동 할아버지 구경꾼, 판이 지날수록 밤.
- 공장 기록: `arcade/experiments/0048-완전히-다른-장르-6개.md`, `arcade/ab.json` 23라운드.

## 오너가 지금까지 준 기준 (공장 23라운드 동안 쌓인 것 — 상용화 판단의 기본값)
1. **조작은 최소로**: 손짓 하나. 끌기·그리기·계속 누르기 금지(피로 없음).
2. **첫 3초 안에 재미**, 첫 손짓에 화면에서 큰 일이 일어난다.
3. **와우 포인트** — "어, 이게 돼?" 하는 규칙 하나. **웃김도 와우다**(표정 있는 주인공, 실패는 벌이 아니라 웃음).
4. **목표·보상이 보인다**: 판마다 분명한 목표와 별 1~3개.
5. **펼쳐짐**: 판이 흐르며 하는 일을 바꾸는 새것이 나온다(같은 동사의 변종 말고).
6. **고민 거리**: 아무렇게나 해도 되는 게임은 안 된다 — 어디서·언제·얼마나의 선택이 결과를 바꾼다.
7. **너무 어렵지 않게**: 첫 판은 거의 못 진다, 실패하면 그 판만 다시.
8. **결과가 읽힌다**: 규칙은 짧게(2줄), 무슨 일이 일어날지 미리 보인다. 복잡한 물리·계산을 사람에게 떠넘기지 않는다.
9. **화면 수준이 높다**: 작은 입체 세계(디오라마), juice(파티클·흔들림·떠오르는 글자), 휴대폰 390px에서 읽힌다.
10. 오너가 버린 이유들: 조작 과다 · 와우 약함 · 너무 어렵거나 금방 죽음 · 화면 밋밋 · 고민 없음 · 결과가 안 읽힘 · 같은 걸 다듬기만 함.

## 마일스톤과 오너 테스트 (오너 지시의 핵심)
1. **M0(첫 사이클)**: 프로토타입을 `studio/sheepdog/`로 옮겨 플레이 빌드를 `web/public/studio/sheepdog/index.html`에 올린다(지금 공장 계기판의 '플레이' 링크가 여기를 가리킴). 기획자 GDD 초안, PM 마일스톤 초안(M1~M5 정도, 마일스톤마다 **테스트 허들**=오너가 무엇을 확인하면 통과인지 명시).
2. 마일스톤마다: 기획(📐) → 디자인(🎨) → 개발 → FUN QA(🧪) → PM QC(📋). 완료 기준·QC를 다 넘으면 PM이 **"오너 빌드 테스트 준비 완료"** 선언.
3. 그 사이클에만 `PushNotification`(무엇을 테스트할지 3줄 + 전체 주소 https://derrick1119.github.io/derrickkim1119/studio/sheepdog/) 하고 STATUS `상태: 오너 테스트 대기`. 기다리는 동안은 새 기능을 만들지 않는다(한 줄 보고).
4. 오너가 **통과**라고 하면 다음 마일스톤. **허들 미달**이면 오너 피드백을 STATUS·TALK에 그대로 적고, PM이 **마일스톤을 재수립**(무엇을 어떻게 고치고 언제 다시 테스트할지)한 뒤 진행한다.
5. 최종 목표: **상용화 수준** — 출시해도 되는 품질(온보딩·콘텐츠 볼륨·메타·저장·사운드·성능·접근성·모바일). 마지막 마일스톤 통과가 졸업.

## 사이클 (예약 작업, 1시간마다 — 발견 공장이 만들어 이 세션에 연결해 둠)

## 가드레일
- 수정할 수 있는 곳은 `studio/sheepdog/`, `web/public/studio/sheepdog/`, `tests/studio-sheepdog*.test.ts` **뿐**. 다른 작업장(`arcade/`, `studio/` 다른 게임, `factory/`, `engine/`, `fusion/`, `web/index.html` 등)은 고치지 않는다.
- `npm run verify` 실패 상태로 push 금지(종료 코드로 판정, 출력을 파이프로 거르지 않는다). 테스트 약화·삭제·skip 금지. push가 거절되면 `git pull --rebase origin factory` → verify → push. force push 금지. `factory` 브랜치에만.
- 런타임 의존성 추가 금지(번들은 esbuild 등 개발 도구로). 외부 서비스 가입·결제·광고 SDK 연동 금지. 비밀값을 저장소에 쓰지 않는다.
- 특정 실존 게임의 이름·캐릭터·아트·레벨을 가져오지 않는다. 결정적 시뮬레이션(봇으로 밸런스 측정)을 유지한다.
- 커밋 메시지: "스튜디오 양치기 멍멍: <요약>" (모델 이름을 넣지 않는다).
- 연속 3사이클 verify 실패로 push 못 하면 STATUS `상태: BLOCKED` + 이유 + 알림.
