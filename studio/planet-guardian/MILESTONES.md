## M4 메타: 다음 판, 내일 판의 이유
**설계**: 저장 계층을 먼저 만들고 그 위에 화폐→소비처→데일리→과제 순으로 쌓는다. 영구 강화는 작게 한다("다음 판이 조금 쉬워진다" 수준, GDD §6).
- [ ] M4-1 저장 계층: localStorage + 메모리 폴백, 스키마 버전, 깨진 데이터 복구, 음소거 설정 저장. 예외가 나도 게임은 멈추지 않는다
- [ ] M4-2 별 조각(점수/10) 정산 + 결과 화면 표시
- [ ] M4-3 사령부: 1갈래 × 5단계(각 +5~10%) + 궤도포 해금을 여기로 옮김

## 일정 규칙
1. 마일스톤이 예상 사이클의 **150%**(위 표의 한도)에 닿으면 PM이 범위 축소를 결정한다. 남은 항목 중 완료 기준과 무관한 것은 다음 마일스톤이나 보류로 옮기고, 이유를 TALK 📋에 남긴다. 완료 기준 자체는 낮추지 않는다. 한도는 처음 추정을 기준으로 하며, 재추정한다고 올리지 않는다.
2. 한 작업 항목이 2사이클 연속 끝나지 않으면 다음 사이클 시작 전에 PM이 반으로 쪼갠다. (C005: 롤아웃 봇 → M2-4a 선결 조건 / M2-4b 봇)
3. FUN 지표 목표를 바꾸려면 FUN QA의 근거(유저군 논리)와 TALK 기록이 있어야 하고, 오너 테스트 요청 때 그 사실을 밝힌다. 통과시키려고 목표를 옮기는 것은 금지다. 개정은 해당 코드 변경보다 먼저 커밋한다.
4. 완료 기준을 모두 넘으면 남은 체크박스와 상관없이 QC로 간다. 남은 항목은 다음 마일스톤으로 넘긴다.
5. 오너 피드백이 오면 다음 사이클은 그 피드백이 최우선이다(1~2사이클, 마일스톤 일정과 별도로 센다). 반영 뒤 다음 마일스톤을 시작한다. 그 사이클에 끝난 마일스톤 항목은 체크하되 사이클 수에는 넣지 않는다.
6. 전체 예산은 M2–M5 27사이클이고 절대 상한은 35다. C003에서 M2 +1, M3 −1, C004에서 M2 +1, **C005에서 M2 +1(롤아웃 봇 쪼갬 + 등급업 편입)로 합계 29(예산 +2)**. 등급업이 M2로 왔지만 M3에 박자·클리어가 들어가 M3는 8로 둔다. M3 시작 때 다시 본다. 35에 닿으면 M5 범위를 PM이 잘라서 끝낸다.
7. 매 사이클 PM은 "지금" 표(진척 %, 다음 오너 테스트 시각 UTC/KST)를 다시 계산한다.

## PM 메모 (기획자에게)
- **C006 범위**: 기준 개정(측정 전에 FUN.md·funqa.ts에 박음) → 난수 상태 숫자화 → 손패 난수 분리 → 램프 복구 순서로 한다. 400줄을 넘으면 H4 실측만 C007로 보낸다. 램프·난수 분리·R1 쌍 비교·L8 개수형은 빼지 않는다.
- **정정 의무**: C005의 "L8은 램프 없이 99초로 통과"는 틀렸다(99초는 램프를 넣고 잰 값, 기준선은 52.5초에 45초 미만 4/24). C006 ✏️ 첫 줄에 정정을 적는다. 앞으로 실험을 폐기할 때는 근거 숫자마다 측정 조건(무엇을 켜고 껐는지, 시드 수)을 함께 적는다.
- L1을 90~180초로 바꾸는 것은 램프를 통과시키려고 목표를 옮긴 것이 아니다. FUN.md의 라이트 체류 2~3분이 근거다(FUN QA C005). 다만 같은 사이클에 램프가 들어가므로, **기준 개정 커밋을 램프 커밋보다 먼저** 하고 오너 테스트 요청 때 밝힌다.
- 난수 분리 뒤에는 모든 시드의 판이 바뀐다. C006에서 funqa 전체(관찰 3종 포함)를 분리 전후로 표로 보고한다. 지난 수치와 비교할 때 분리 전후를 섞지 않는다.
- 롤아웃 봇(C007)은 복제한 State에서만 미래를 본다. 원본 난수를 들여다보면 투시 봇이 된다. 선택지는 State에서 나열해 C008 등급업이 코드 수정 없이 들어가게 한다.
- 원탭 능력(쿨다운 있는 역회전·순간 가속)은 STATUS "오너에게"의 결정 요청으로 둔다. M2 일정은 이 답에 기대지 않는다. 승인되면 M3-5에서 함께 구현한다.
