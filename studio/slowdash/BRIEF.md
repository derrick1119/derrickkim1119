> 게임 발견 공장(`arcade/`) 31라운드에서 오너가 고른 게임(2026-11-19)을 **상용화 수준의 게임 하나**로 만드는 팀의 작업장.

> "4번 스튜디오 개설하고 인력 붙여서 진행해 나사 풀기 공방 스튜디오처럼" · "나머지는 다 폐기" (2026-11-19, 31라운드 판정)
> 스튜디오 운영 방식(2026-11-12, 23라운드 졸업 때):
> "따로 세션으로 보내서 개발을 진행하자. 전문 기획자를 붙여서 컨텐츠랑 시스템을 디테일하게 기획해주고, 개발자가 그걸 보고 반영을 해. 그리고 디자이너가 상용화 수준으로 알맞은 컨셉과 퀄리티의 리소스를 제작해. 그리고 fun QA가 계속해서 재미를 검증해줘. 그리고 PM은 마일스톤을 수립한뒤에 각 마일스톤 달성 시마다 나한테 빌드 테스트를 요청해. 마일스톤 테스트 허들을 넘지 못하면 부족한 부분을 피드백줄테니까 마일스톤을 재수립해서 진행해. 최종 목표는 상용화야. 상용화 수준에 맞는 게임을 하나 만드는 팀들을 운영하는거야. 각 아이디어가 각 팀이 되는거지."

## 출발점
- 프로토타입: `arcade/games/slowdash.ts` — **읽기만** 한다(공장 소유, 공장 레지스트리에서는 빠지고 참고용 파일로만 남음). 코드는 복사해서 `studio/slowdash/`에서 새로 키운다.
- 한 줄: 꾹 누르면 세상이 먹빛 회색 슬로모션이 되고 닌자에서 손가락까지 돌진 선이 보인다 — 떼는 순간 '번쩍!' 그 선 위의 적을 한 번에 베고 지나간다. 느린 시간 게이지는 누르는 동안·긴 돌진에 줄고, **한 줄에 여럿을 벨 때만 찬다** → 기다려 줄 세우기 vs 비키기.
- 조작: 꾹 → 떼기(touch, 누르는 동안 손가락으로 겨눔). 닌자 위에서 떼면 취소. 키보드 화살표 커서+스페이스.
- 프로토타입 현황(공장 측정, 실험 `arcade/experiments/0074-실시간-액션-6개.md`):
  - 8판(대숲 입구 허수아비 → 칼잡이 너구리 → 화살병 개구리 → 수리검 까마귀 → 방패 무사 멧돼지(등 뒤로 베기) → 폭탄 통(꾀어 모아 연쇄) → 거울(선이 꺾임) → 대장 곰+연기).
  - 별: 숲 지나가기 · 한 번에 셋 베기 · 한 번에 다섯 베기 등 판마다 쉬운 말. 체력 3, 다 잃으면 하트 -1(그 판만 다시).
  - 측정: 재미 0.962, 숙련 격차 7.05×, 첫 손짓 → 3명 베기 즉시(떼는 순간), 처음 10초에 무작위 봇 패배 0/100, 무작위 1판 96% · 2판 54%, 버릇 봇 ★3(3판~) 0%.
  - 그림: 이모지 없이 캔버스로 직접 그린 여우 닌자·너구리·개구리·까마귀·멧돼지·곰, 달밤 대숲 시차 층, 느린 시간 회색 화면과 칼빛 대비, 먹물 붓자국 '3명 베기!' 띠.
- 프로토타입 약점(에이전트·공장 보고): 밤이라 화면이 전체적으로 어둡고 땅 가운데가 비어 보임 · 캐릭터가 폰에서 작음(폭 0.18) · HUD에 큰 둥근 단추·재질감 부족 · 소리 없음 · 무작위 2판 54%(경계) · 봇은 판당 4~11초(사람은 15~30초 예상) · 파일 3705줄(그리기 코드가 장황).
- **닮은 게임(솔직히)**: 느린 시간에 겨누고 돌진해 베기는 인디 액션(카타나 계열)·시간 조작 슈터와 닮았고, 모바일에도 선 긋고 베는 캐주얼이 있다. 우리 것 = 누르는 시간과 선 길이가 같은 게이지를 쓰고 여럿을 벨 때만 차는 경제, 연쇄, 판마다 하는 일을 바꾸는 새것(방패 등 뒤·통 꾀기·거울 꺾기·연기 숨기). **이 비틀기를 키워 차별화**하고 특정 게임의 이름·캐릭터·레벨·UI를 닮지 않게 한다.

## 오너가 지금까지 준 기준 (공장 31라운드 동안 쌓인 것 — 상용화 판단의 기본값)
1. **첫인상이 1순위**(31라운드 오너 답: 버린 이유 "첫인상이 재미없음 · 뻔하거나 이미 있음 · 그래픽·연출이 아쉬움"): 화면이 뜨자마자 움직이고, 첫 손짓 1초 안에 '우와'가 온다. 읽을 것 없이 손이 먼저 간다.
2. **뻔하지 않음**: 이미 있는 게임처럼 느껴지면 버려진다(물약 정렬 스튜디오 폐기 이유 "이미 너무 뻔하게 있는 아이디어"). 우리만의 핵심 손맛을 키운다.
3. **그래픽·연출은 상용 게임 수준**: 직접 그린 캐릭터(윤곽·명암·표정·애니메이션), 층 있는 배경, 맞는 순간 멈칫·흔들림·잠깐 느려짐·파티클, 연속일수록 커지는 쾌감. 폰에서 렉 없이.
4. **조작은 손짓 하나**(15라운드 "조작이 너무 필요해서 별로"): 꾹-떼기. 자잘한 연타·번거로움 금지("하나씩 눌러서 넣는게 번거로울 때가 있어").
5. **너무 어렵지 않게**(16라운드 "너무 어려움·금방 죽음"): 첫 판은 거의 못 진다, 실패하면 그 판만 다시.
6. **목표·별·지는 조건은 기호 없는 쉬운 말**, 단계별로 하나씩 배우게(나사 공방 M2·M3 피드백).
7. **펼쳐짐**: 판이 흐르며 하는 일을 바꾸는 새것(같은 동사의 변종 말고), 새것은 NEW 스포트라이트.
8. **전략 깊이**(양치기 멍멍 "전략이 조금 단순해지는 느낌"): 버릇 하나로 ★3이 나오면 안 된다. 무엇을 먼저·언제·어디로가 판마다 달라야 한다.
9. **웃김도 와우다**: 표정 있는 주인공, 실패는 벌이 아니라 웃음, 구경꾼 반응.
10. **화면이 읽힌다**: 휴대폰 390px(캔버스 약 340px)에서 글자 12px 이상, 주인공·적은 충분히 크게.
11. 오너가 버린 이유들: 조작 과다 · 와우 약함 · 너무 어렵거나 금방 죽음 · 화면 밋밋 · 고민 없음 · 결과가 안 읽힘 · 뻔함 · 첫인상 · 그래픽.
12. **먼저 졸업한 팀들의 오너 테스트 결과**(참고): 🔩 나사 풀기 공방 M1′·M2′·M3 통과(살아 있음) · 🦆 욕조 물결 오리 M1 통과 · 🐑 양치기·🎈 풍선·🚌 버스·💥 철거·🧪 물약은 스튜디오에서 폐기. **매 마일스톤에서 코어 재미·첫인상·그림이 바로 느껴져야 한다.**

## 마일스톤과 오너 테스트 (오너 지시의 핵심)
1. **M0(첫 사이클)**: 프로토타입을 `studio/slowdash/`로 옮겨 플레이 빌드를 `web/public/studio/slowdash/index.html`에 올린다. 기획자 GDD 초안, PM 마일스톤 초안(M1~M5 정도, 마일스톤마다 **테스트 허들**=오너가 무엇을 확인하면 통과인지 명시).
2. 마일스톤마다: 기획(📐) → 디자인(🎨) → 개발 → FUN QA(🧪) → PM QC(📋). 완료 기준·QC를 다 넘으면 PM이 **"오너 빌드 테스트 준비 완료"** 선언.
3. 그 사이클에만 `PushNotification`(무엇을 테스트할지 3줄 + 전체 주소 https://derrick1119.github.io/derrickkim1119/studio/slowdash/) 하고 STATUS `상태: 오너 테스트 대기`. 기다리는 동안은 새 기능을 만들지 않는다(한 줄 보고).
4. 오너가 **통과**라고 하면 다음 마일스톤. **허들 미달**이면 오너 피드백을 STATUS·TALK에 그대로 적고, PM이 **마일스톤을 재수립**(무엇을 어떻게 고치고 언제 다시 테스트할지)한 뒤 진행한다.
5. 최종 목표: **상용화 수준** — 출시해도 되는 품질(온보딩·콘텐츠 볼륨·메타·저장·사운드·성능·접근성·모바일). 마지막 마일스톤 통과가 졸업.

## 사이클 (예약 작업, 1시간마다 — 발견 공장이 만들어 이 세션에 연결해 둠)
- 동기화(`git fetch origin factory && git checkout factory && git pull --rebase origin factory`, 필요하면 `npm ci`) → STATUS·MILESTONES·TALK 맨 위 읽기 → 멈춤 확인(`오너 테스트 대기`면 오너 피드백이 있을 때만 반영, 없으면 한 줄 보고) → 이번 마일스톤 작업 1~2개(diff 약 400줄 이내) → 측정(build·funqa·shots·verify) → FUN QA → 응답 → PM → 기록 → 커밋·푸시 → 배포 확인.
- 사이클 끝 한국어 3줄 요약. **오너에게 보이는 첫 줄은 플레이 주소 https://derrick1119.github.io/derrickkim1119/studio/slowdash/**.
- 오너와 대화는 한국어로만.

## 결과물 위치와 공개
- 코드·문서: `studio/slowdash/`, 테스트: `tests/studio-slowdash*.test.ts`
- 플레이 빌드: `web/public/studio/slowdash/` → `factory` 브랜치에 push하면 GitHub Pages 자동 배포: **https://derrick1119.github.io/derrickkim1119/studio/slowdash/** (오너가 승인한 공개 주소. 이 환경에서는 github.io 직접 접속이 막혀 있으니 배포 확인은 GitHub Actions `deploy` 결과로.)

## 가드레일
- 수정할 수 있는 곳은 `studio/slowdash/`, `web/public/studio/slowdash/`, `tests/studio-slowdash*.test.ts` **뿐**. 다른 작업장(`arcade/`, `studio/` 다른 게임, `factory/`, `engine/`, `fusion/`, `web/index.html` 등)은 고치지 않는다.
- `npm run verify` 실패 상태로 push 금지(종료 코드로 판정, 출력을 파이프로 거르지 않는다). 테스트 약화·삭제·skip 금지. push가 거절되면 `git pull --rebase origin factory` → verify → push. force push 금지. `factory` 브랜치에만. 다른 팀의 작업 파일을 stash·checkout으로 건드리지 않는다.
- 런타임 의존성 추가 금지(번들은 esbuild 등 개발 도구로). 외부 서비스 가입·결제·광고 SDK 연동 금지. 비밀값을 저장소에 쓰지 않는다.
- 특정 실존 게임의 이름·캐릭터·아트·레벨을 가져오지 않는다. 결정적 시뮬레이션(봇으로 밸런스 측정)을 유지한다.
- 커밋 메시지: "스튜디오 느린 시간 닌자: <요약>" (모델 이름을 넣지 않는다).
- 연속 3사이클 verify 실패로 push 못 하면 STATUS `상태: BLOCKED` + 이유 + 알림.
