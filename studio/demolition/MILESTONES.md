## M1 코어+전략: 쾅이 손에 붙고, 아끼는 고민이 생긴다 (7사이클, 한도 10)
**왜**: 기준선에서 탐욕 봇이 ★3을 5/7판에서 딴다. 미리 보기만 따라 해도 깨지므로 기준 11 위반이다. 또 기둥이 390px에서 빗나가고(기준 1), 하트는 "그 판만 다시"(기준 7)와 부딪힌다. 셋 중 하나라도 남으면 오너가 M1에서 바로 느낀다.
- **포함**
  1. GDD §4 **A안**: 기폭 손잡이(톡 = 지금 쾅) + ★3 = **아끼기**(반장 목표 수 이하 + ★2), 남은 폭약은 축포 연출. 1-1~1-3은 ★3 = 납작.
  2. **D 설계 규칙**: 1-5부터 미끼 칸을 두고, ★3 계획의 첫 폭약은 혼자 쾅 하면 '꿈쩍 안 함'이 되게 짠다.
  3. **판: 1월드 중 7판** = 1-1~1-6 + 1-8 도미노(프로토타입 재사용 5 · 새로 1-3 기우뚱 굴뚝, 1-4 예비 폭약 창고). 1-7·1-9·1-10은 M2로. 쇠 다리 망루는 2-1로.
  4. **조작**: 자석 겨누기(반경 0.9칸, 붙일 수 없는 칸은 건너뜀) + 현장 맞춤 줌 + 겨눔 확대 말풍선(GDD §8 1·2·3).
  5. **하트 제거**: 실패하면 1.2초 웃음(빗자루·머쓱한 헬멧) 뒤 그 판만 즉시 다시 · ↺ 상시 · 3실패 → 첫 폭약 힌트 1회 · 판별 최고 별 저장(막히면 메모리).
  6. **ART M1 손맛**(ART §10 1~5): 노랑 겨눔 테 · 라이트 노을 팔레트 + 블록 꼭지 · 미리 보기 유령 문법 1~5 · HUD 56px(폭약 × 남은 수, 손잡이, 별 칩 실시간 ✓✕) · 히트스톱·"쾅!" 글자·비네트 느린 화면 · 효과음 탁·삑·쾅·와르르.
- **제외**: 판 고르기 지도, DOM 결과 카드 완성본, 비버·할머니 전 표정, 2·3월드 재료, 사운드 나머지, 메타·데일리.
- **사이클 배정**: C002 FUN v1 + 손잡이·아끼기 엔진 + 하트 제거 / C003 greedy1·look2 봇 + `studio-demolition-depth.test.ts` + 1-1~1-4 / C004 1-5·1-6·1-8 미끼 재설계(판 7/7) / C005 자석·줌·확대 말풍선 + 떨리는 손가락 봇 / C006 팔레트·꼭지·유령 문법·HUD / C007 쾅 juice·효과음 4종·실패 웃음 / C008 빚 갚기 + QC → 테스트 요청. 40분이 지나면 남은 판은 다음 사이클로 넘긴다.
- **완료 기준(기계, 시드 20 × 뒤집기 2)**
  - 탐욕 봇 `greedy1` ★3률: 1-5 이후 판마다 **≤ 0.2**, 소개 판(1-4) ≤ 0.4 · ★1 클리어 ≥ 0.9.
  - 2수 봇 `look2` ★3 ≥ 0.6 · 철거 박사 ★3 = 1.0(7판 전부) · **깊이 사다리** greedy1 < look2 ≤ 박사가 도전 판 100%에서 성립.
  - 버릇 봇 ★3 = 0 · 무작위 1-1 첫 시도 클리어 ≥ 0.95 · 처음 봇 5회 안 클리어: 소개 판 ≥ 0.9, 그 밖 ≥ 0.6.
  - 떨리는 손가락 봇(σ 0.45칸, 390×844): 의도한 블록 적중 ≥ 0.95, 빈칸 취소 ≤ 0.03.
  - 테스트: 손잡이 쾅도 미리 보기 = 실제 · 실패 → 같은 판 재시작 · 저장 불가 환경 진행 · 결정성 · 하트 코드 0.
  - 스크린샷 390px: 1-1 첫 톡 · 1-4 손잡이 + 축포 · 유령 미리 보기 · 실패 빗자루 · 결과 별. 글자 ≥ 16px, 버튼 ≥ 44px · gzip ≤ 30KB · FUN 재미 ≥ 0.9, 숙련 격차 ≥ 3×(보고).
- **오너 테스트 허들** (휴대폰으로)
  1. 아무것도 안 읽고 1판 기둥을 톡 하면 3초 안에 3·2·1 쾅, 탑이 와르르 무너지고 할머니 "휴~"에 웃음이 난다. 좁은 기둥도 한 번에 눌린다.
  2. 1-4 이후 판에서 미리 보기대로 붙이면 ★1~2는 쉽게 나오는데, ★3은 "폭약 하나 아끼려면 어디를 먼저?"를 한 번 생각해야 나온다. 손잡이로 일찍 쾅 하는 게 짜릿하다.
  3. 이웃집을 쳐도 벌이 아니라 웃기고(빗자루), 그 판만 바로 다시 해서 "한 판 더"가 든다.

1. 150% 한도에 닿으면 PM이 범위를 줄인다(완료 기준과 무관한 항목을 다음으로). **완료 기준은 낮추지 않는다.**
2. 한 작업이 2사이클 연속 안 끝나면 반으로 쪼갠다. 판 하나에 실험 값을 3번 넘게 쓰면 그 판을 재설계 목록으로 보낸다.
3. FUN 목표 개정은 🧪 근거와 TALK 기록이 있어야 하고, 코드보다 먼저 커밋한다. 테스트 요청 때 밝힌다. 통과시키려고 목표를 옮기지 않는다.
4. 완료 기준을 다 넘으면 QC로 간다. 남은 항목은 다음으로 넘긴다.
5. '오너 테스트 대기' 중에는 새 기능을 만들지 않는다(한 줄 보고).
6. 매 사이클 "지금" 표(진척 %, 다음 테스트 UTC/KST, 예산)를 다시 계산한다.

## 재수립 규칙 (허들 미달일 때)
- **R1 원문 그대로**: 오너의 말을 STATUS와 TALK 맨 위(💬)에 그대로 적는다. 해석은 그 아래에 한다.
- **R2 피드백 사이클 F01·F02**: 다음 사이클은 피드백이 최우선이다(최대 2사이클, 일정 밖). ① 말을 숫자로 먼저 잰다(예: "전략이 단순" → 판별 greedy1·look2 ★3률, 버릇 봇) ② 고칠 것과 폐기 기준을 정한 뒤 고친다.
- **R3 마디별로**: (a) 이번 허들 미달이면 이번 마일스톤에서 고친다 (b) 뒤 범위면 그 마일스톤으로 옮기고 이유를 쓴다 (c) 지표가 못 잡은 것이면 FUN 기준을 먼저 새로 만든다. 오너의 말이 재미의 유일한 진짜 측정값이다.
- **R4 다시 쓴다**: 해당 마일스톤에 "재수립 N차" 절을 붙인다(미달 → 어떻게 → 새 완료 기준·허들(오너 말을 뒤집은 문장) → 재테스트 예상 시각). 뒤 마일스톤의 사이클·한도도 다시 계산한다.
- **R5 다시 요청**: QC를 다시 통과하면 같은 마일스톤 테스트를 한 번 더 요청한다. F02 뒤에도 미달이면 마일스톤을 둘로 쪼개 먼저 고칠 절반만 다시 받는다. M1에서 "전략 단순"이 다시 나오면 GDD §4 C안(차례 폭발)을 1월드 기믹으로 당겨 오는 것을 첫 후보로 둔다.
- **R6 통과**: "통과"·"다음"이면 ✅로 바꾸고 다음 마일스톤을 시작한다. 부분 통과면 통과한 허들만 ✅, 나머지는 R3으로 처리한다.
