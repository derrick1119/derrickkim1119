## 규칙 발명 (공장의 본업)
- [x] (0003) **플레이테스트 모드**: 웹에서 `?play=<규칙id>&seed=<n>&tier=<난이도>`로 아무 규칙 퍼즐이나 브라우저에서 즉석 생성해 플레이. 오너가 후보 규칙을 직접 만져볼 수 있게 하는 것이 목적 (규칙 설명 문구는 RuleSet.rules 사용). e2e에 한 케이스 추가.
- [ ] **인지 부하 지표**: 단서당 세어야 할 칸 수(고리 크기 평균)와 고리 겹침도를 evaluate에 추가하고 fitness에 페널티 항으로 반영. 0002의 d=3 우세가 유지되는지 재탐색.
- [ ] **탐색 공간 확장**: 단서 종류 축 추가 — 정확한 수 / 홀짝 / "두 고리(d1, d2)의 차". 상위 3개를 n=20으로 재검증해 노이즈 배제.
- [x] (0002) **규칙 계보 탐색기**: `echo`를 매개변수화한 규칙 패밀리(고리 거리 d∈{1,2,3}, 거리 척도 체비셰프/맨해튼, 전역 규칙 맞닿기금지/없음/2×2금지)를 만들고 `evaluate`를 격자 탐색해 `factory/reports/family.json`에 순위표를 낸다. 기존 장르와 같아지는 조합(d=1 체비셰프 = 지뢰찾기류)은 표시만 하고 제외.
- [ ] **두 번째 오리지널 규칙**: 인지 부하 반영 후 탐색기 상위 결과 또는 발상 규칙 조합으로 새 규칙 1개를 id를 새로 붙여 추가하고 echo와 지표 비교.
- [ ] **'거짓말쟁이' 변형**: 단서 중 정확히 하나가 틀렸다는 규칙. 엔진은 제약 대신 "제약 집합 중 하나 위반"을 지원해야 함 — 엔진 확장 비용을 먼저 견적.
- [ ] **재미 지표 고도화**: 풀이 중 "병목 단계"(그 시점에 가능한 추론이 1개뿐인 단계) 수, 추론이 판 전체로 퍼지는 정도(공간 분산)를 rate()에 추가.

- [ ] **규칙별 힌트 설명 훅**: `RuleSet.explain?(step, puzzle)`를 추가해 힌트 문구를 규칙이 제공. 0003에서 fam-* 규칙 힌트가 echo 문구("고리")에 기대고 있음을 확인.
