## A|B 루프 (0006~, 도전자 풀) — 모든 후보는 단순함 게이트 먼저
- [ ] **xline-notouch 적중률 0.80 → 0.9**: 재미 0.663으로 게이트 통과 후보 중 최고. 어려움 생성 보정(크기·attempts). 3라운드 후보.
- [ ] **직선형 변형**: '숫자 칸에서 처음 만나는 칠한 칸까지의 거리' 같은 줄 기반 단서는 [min,max]로 표현 가능한지 견적. 십자(cross)의 어려움 적중률 0.55–0.70 원인 분석도 함께.
- [ ] **이해도 실측**: 계기판에 '규칙 이해에 걸린 시간' 셀프 체크(1초 버튼)를 넣어 오너의 체감을 숫자로 받기.
- [~] (0007 폐기: 단순함 게이트 탈락) **나이트 메아리 어려움 적중률 0.887 → 0.9**: fam-d1-knight-notouch는 재미 공동 1위(0.638)인데 어려움 적중률만 미달. 어려움 생성 attempts·크기(7→8) 조정 또는 trial 기준 점검. 통과하면 2라운드 도전자 1순위.
- [ ] **재미 지표 검증**: 오너의 1라운드 선택이 나오면 재미 지표(긴장·퍼짐·아하)의 예측과 비교. 틀렸으면 가중치 조정 가설.
- [ ] **새 축 도전자**: 발상 규칙의 '단서 형태' 축(홀짝 / 이웃 단서보다 크다)은 [min,max] 제약으로 표현 불가 → 엔진에 '허용 개수 집합' 제약(예: {0,2,4,…}) 지원 비용 견적.

## 규칙 발명 (공장의 본업)
- [x] (0003) **플레이테스트 모드**: 웹에서 `?play=<규칙id>&seed=<n>&tier=<난이도>`로 아무 규칙 퍼즐이나 브라우저에서 즉석 생성해 플레이. 오너가 후보 규칙을 직접 만져볼 수 있게 하는 것이 목적 (규칙 설명 문구는 RuleSet.rules 사용). e2e에 한 케이스 추가.
- [x] (0004) **인지 부하 지표**: 단서당 세어야 할 칸 수(고리 크기 평균)와 고리 겹침도를 evaluate에 추가하고 fitness에 페널티 항으로 반영. 0002의 d=3 우세가 유지되는지 재탐색.
- [x] (0005) **상위 4개 n=20 재검증**: 0004에서 1~4위(fam-d3-cheb-no2x2, fam-d1-cheb-notouch, fam-d3-manh-notouch, fam-d2-manh-notouch)가 fitness 0.486–0.488로 n=6 노이즈 안 동률. explore에 `--only <id,...>` 옵션 추가 후 n=20, 시드 집합 2개로 재평가해 순위 신뢰구간을 낸다.
- [ ] **explore 기본을 다중 시드로**: 0005에서 n=6 단일 시드 순위가 뒤집힘(1위→4위). explore를 n=10 × 시드 집합 2개로 바꾸고 순위표에 sd를 함께 낸다(예상 ~4분). 이후 모든 규칙 비교는 sd 기준으로 판정.
- [ ] **판 크기 민감도(ringClip)**: 같은 규칙을 size 6/8/10으로 평가해 fitness가 판 크기에 얼마나 흔들리는지 측정. d=3 체비셰프는 고리 47–62%가 판 밖이라 큰 판에서 성질이 바뀔 가능성.
- [ ] **탐색 공간 확장**: 단서 종류 축 추가 — 정확한 수 / 홀짝 / "두 고리(d1, d2)의 차". 상위 3개를 n=20으로 재검증해 노이즈 배제.
- [x] (0002) **규칙 계보 탐색기**: `echo`를 매개변수화한 규칙 패밀리(고리 거리 d∈{1,2,3}, 거리 척도 체비셰프/맨해튼, 전역 규칙 맞닿기금지/없음/2×2금지)를 만들고 `evaluate`를 격자 탐색해 `factory/reports/family.json`에 순위표를 낸다. 기존 장르와 같아지는 조합(d=1 체비셰프 = 지뢰찾기류)은 표시만 하고 제외.
- [ ] **두 번째 오리지널 규칙**: (0005 결과: 1순위 fam-d3-manh-notouch — 점수 공동 1위, sd 최소. fam-d1-cheb-notouch는 지뢰찾기 변형류라 보류) 인지 부하 반영 후 탐색기 상위 결과 또는 발상 규칙 조합으로 새 규칙 1개를 id를 새로 붙여 추가하고 echo와 지표 비교.
- [ ] **'거짓말쟁이' 변형**: 단서 중 정확히 하나가 틀렸다는 규칙. 엔진은 제약 대신 "제약 집합 중 하나 위반"을 지원해야 함 — 엔진 확장 비용을 먼저 견적.
- [x] (0006) **재미 지표 고도화**: 풀이 중 "병목 단계"(그 시점에 가능한 추론이 1개뿐인 단계) 수, 추론이 판 전체로 퍼지는 정도(공간 분산)를 rate()에 추가.

- [ ] **규칙별 힌트 설명 훅**: `RuleSet.explain?(step, puzzle)`를 추가해 힌트 문구를 규칙이 제공. 0003에서 fam-* 규칙 힌트가 echo 문구("고리")에 기대고 있음을 확인.
