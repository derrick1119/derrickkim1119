# 0008 — xline-notouch 적중률: 규칙 문제인가, 평가 예산 문제인가

## 진단 (코드 수정 전)
abtest/explore는 생성 시도 attempts=20으로 평가하지만, 실제 제품은 데일리 은행 80, 플레이테스트 40을 쓴다.
xline-notouch 어려움(7×7) 20퍼즐 사전 측정: attempts 20 → 적중 17/20 (274ms), attempts 40 → 20/20 (319ms), 8×8은 지옥으로 넘침.

## 가설
xline-notouch의 적중률 미달(0.80)은 규칙이 아니라 **평가 예산이 제품보다 작아서** 생긴 착시다.
abtest를 제품과 같은 예산(attempts 40 = 플레이테스트, 은행보다 보수적)으로 바꾸면 전 난이도 적중 ≥ 0.9, 어려움 생성 ≤ 2s로 자격을 얻는다.

## 측정
- `npm run abtest -- --attempts 40` (기본값을 40으로), n=20 × 4: echo, xline-none, xline-notouch, xline-no2x2.
- 2라운드 B는 바꾸지 않는다(프로토콜). 결과는 3라운드 후보 풀에 반영.

## 폐기 기준
- attempts 40에서 xline-notouch 최저 적중 < 0.9 또는 어려움 생성 > 2s → 예산 변경은 되돌리고 원인을 '규칙'으로 기록.

## 결과 (n=20 × 4, attempts 40, 102초) → **가설 채택**
| 규칙 | 재미 | fitness | 최저 적중 (20→40) | 어려움 ms | 자격 |
|---|---|---|---|---|---|
| **fam-d1-xline-notouch** | **0.658 ± 0.010** | **0.503** | 0.80 → **0.95** | 402 | ✓ (신규) |
| fam-d1-xline-no2x2 | 0.633 ± 0.011 | 0.495 | 1.00 → 1.00 | 64 | ✓ |
| fam-d1-xline-none (2라운드 B) | 0.611 ± 0.013 | 0.494 | 0.93 → 1.00 | 18 | ✓ |
| echo (A) | 0.581 ± 0.012 | 0.456 | 0.81 → 0.975 | 429 | 게이트 ✗ |

- 미달은 규칙이 아니라 평가 예산 착시였다. echo의 어려움 적중률도 0.81 → 0.975로 올랐다 (0001~0007의 '0.93' 등은 과소평가).
- xline-notouch는 xline-none보다 재미 +0.047 (2×sd 0.026 초과 → 확실). 규칙 문장 3개(숫자 + 맞닿기 금지)지만 게이트 범위 안.
- 2라운드 B는 프로토콜대로 유지. xline-notouch는 **3라운드 도전자 1순위**로 기록.

## 배운 것
- 평가 조건은 제품 조건과 같아야 한다. explore/reverify(attempts 20)의 과거 순위도 같은 편향을 갖고 있다.
