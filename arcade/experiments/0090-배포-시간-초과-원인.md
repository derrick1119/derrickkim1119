# 0090 — 배포 시간 초과 원인 찾음: 60초 넘게 쉬지 않는 테스트 파일 (코드 변경 없음)

## 왜
- 0085 뒤에도 배포가 같은 오류로 실패했다: 33라운드(611c86d) 배포가 두 번 연속 `[vitest-worker]: Timeout calling "onTaskUpdate"`(테스트 393개는 모두 통과), 세 번째에 성공.

## 가설
- vitest 작업자는 메인에 진행 상황을 보내고 **60초 안에 답을 받아야** 한다(birpc 기본 60초). 한 테스트 파일이 쉬지 않고(동기 계산만) 60초 넘게 돌면 그동안 답을 처리하지 못해, 끝난 뒤 시간 초과로 친다.

## 측정
1. **재현** (scratch, 저장소 밖): 9초짜리 동기 계산 테스트 8개(72초)인 파일 하나 →
   - 그대로: 테스트 8개 통과 + `Timeout calling "onTaskUpdate"` 1개 — CI와 똑같다.
   - 테스트마다 앞에 `beforeEach(() => new Promise((r) => setTimeout(r, 0)))`(아주 잠깐 쉬기): 오류 없음.
2. **CI 파일별 시간** (실패한 배포 885 두 번째 실행):

| 파일 | CI 시간 | 소유 |
|---|---|---|
| `tests/studio-duckbath.test.ts` | **68.4초** (60초 초과) | 욕조 물결 오리 스튜디오(예약 꺼짐) |
| `tests/studio-planet-guardian.test.ts` | 49.4초 | 행성 수호대 스튜디오(예약 꺼짐) |
| `tests/studio-animalbus.test.ts` | 41.3초 | 동물 버스(폐기) |
| 그 밖 | 14초 이하 | — |

- 욕조 파일은 로컬 38초, CI 68초 — CI가 느려 60초 언저리를 오가니 실패가 가끔 몰린다(0085의 '흔들림').

## 판정
- 원인은 욕조 물결 오리 스튜디오의 테스트 파일 하나다. 발견 공장 테스트(arcade 10초)와 무관하다.
- 테스트를 약화하지 않는 고침 두 가지(둘 다 발견 공장 밖이라 오너에게 여쭘):
  - **A (추천)**: 공용 `vite.config.ts`에 `setupFiles` 한 줄 + 새 파일 `tests/setup-yield.ts`(모든 테스트 앞에서 0초 쉬기). 어떤 팀의 테스트도 바꾸지 않고, 앞으로 무거운 파일이 생겨도 막는다. 재현 시험으로 확인함.
  - B: 욕조 스튜디오 테스트를 두 파일로 나누기(스튜디오 영역, 예약이 꺼져 있어 지금은 할 사람이 없음).
- 답을 받기 전엔 실패한 배포를 다시 돌린다(빈 커밋 없이).
