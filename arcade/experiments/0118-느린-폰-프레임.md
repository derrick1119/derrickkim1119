# 0118 — 느린 폰에서 끊기나 (38라운드 판정 대기 중)

## 가설
38라운드 셋은 4천~6천 줄짜리 게임(그림·입자·소리)이다. 오너는 폰으로 해 볼 수 있는데, 지금까지 프레임은 잰 적이 없다.
손맛·첫인상(폐기 이유 상위)은 끊기면 바로 무너진다. 실제 브라우저에서 CPU를 4배 느리게(중간급 폰 흉내) 하고
시작 → 기다림 → 톡·긋기 동안 프레임 간격을 재면 끊김이 보인다.

## 측정
- Playwright Chromium, 390px, CDP `Emulation.setCPUThrottlingRate` 4. 게임마다 8초(기다림 3초 + 톡·긋기 5초) 동안 requestAnimationFrame 간격.
- 지표: 중앙값 ms, 95번째 ms, 50ms 넘는 프레임 비율(눈에 띄는 끊김). 비교로 느리게 하지 않은 값(1배)도.
- 기준: 4배에서 중앙값 ≤ 20ms(≈50fps), 50ms 넘는 프레임 ≤ 5%.

## 폐기 기준
- 이 컨테이너의 CPU 자체가 1배에서 기준을 못 넘으면(중앙값 > 20ms) 측정이 의미 없음 → 도구만 남기지 않고 기록만.
- 셋 다 기준 통과면 코드 변경 없이 점검 도구를 키트에 남긴다(채택). 못 넘는 게임이 있으면 원인(그리기·입자 수)만 찾아 적고, 열린 라운드 게임은 고치지 않는다(오너가 해 보는 중 — 고침은 졸업 뒤 스튜디오 몫).

## 결과 — 채택 (점검 도구만, 게임 코드 변경 없음)
| 게임 | 1배·화소 3배 간격 | 4배·화소 3배 간격(50ms 넘음) | 4배·화소 1배 간격 | **게임 코드 4배 중앙 / p95** |
|---|---|---|---|---|
| 🪶 무게 훔치기 | 16.7ms | 83ms (100%) | 33ms | **8.4 / 13.0ms** |
| ⏪ 한 물건만 되감기 | 16.7ms | 83ms (100%) | 16.7ms | **7.1 / 19.5ms** |
| ↔️ 크기 바꾸기 | 16.7ms | 50ms (15%) | 16.7ms | **3.9 / 7.4ms** |

- 1배에선 셋 다 60fps 그대로(폐기 기준의 '컨테이너가 원래 느림'은 아님).
- 4배에서 간격이 무너지는 건 **화면 칠하기(래스터)** 쪽: 화소 3배→1배로 줄이면 되감기·크기는 60fps로 돌아온다. 이 컨테이너의 헤드리스 Chromium은 GPU 없이 CPU로 칠하므로, GPU로 칠하는 실제 폰보다 크게 과장된다 — 여기서는 잴 수 없다.
- 게임 코드(rAF 콜백 = 계산 + 그리기 명령) 자체는 4배에서도 중앙 4~8ms로 한 프레임(16.7ms) 안. 되감기만 p95 19.5ms — 큰 되감기 순간에 가끔 한 프레임 놓칠 수 있음. 비싼 효과(그림자 흐림·필터)는 거의 안 씀.
- 판단: 폰에서 끊긴다는 증거는 없음. 열린 라운드 게임은 고치지 않음. 되감기가 졸업하면 스튜디오 BRIEF에 'p95 19.5ms(4배)'를 적는다.
- 도구 `arcade/kit/frame-check.cjs id들 [배수] [화소배수]` — 볼 숫자는 '게임 코드'(간격은 헤드리스에선 칠하기에 묶임).
