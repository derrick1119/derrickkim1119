5. **기획 = 진짜 고민**(38라운드 "기획적 요소를 다듬어야"): 판마다 손댈 것 ≥ 3, 그럴듯한 오답(함정), 순서·때가 중요. 버릇 하나로 ★3이 나오면 안 된다(3판부터 버릇 봇 ★3 < 50%).
6. **조작은 쉽게**(33라운드 "조작이 어색하거나 어려움"): 톡(또는 톡 → 톡). 꾹 모으기·좁은 타이밍·당겨 겨누기·연타·문지르기 금지. 손가락이 3% 어긋나도 점수 ≥ 0.7.

## 마일스톤과 오너 테스트 (오너 지시의 핵심)
1. **M0(첫 사이클~두 사이클)**: 프로토타입에서는 **규칙(결정적 시뮬레이션·봇)만** 가져간다 — 그림·UI·연출은 가져가지 않는다(💬 오너 2026-11-21, 몸 갈아타기 스튜디오: "프로토타입 게임 핵심 시스템만 살리라는거지 그대로 이어서 하라는게 아니엇어"). 첫 사이클의 결과물은 **새 그림 컨셉 시안 2~3장**(같은 장면을 서로 다른 그림 방향으로, 휴대폰 크기 스크린샷)과 기획자 GDD 초안 — 오너가 시안을 고르면 그 방향으로 플레이 빌드를 `web/public/studio/{{ID}}/index.html`에 올린다. PM 마일스톤 초안(M1~M5 정도, 마일스톤마다 **테스트 허들**=오너가 무엇을 확인하면 통과인지 명시). 3D/WebGL을 쓰면 **아이폰 사파리에서 먼저** 확인한다(애플 GPU에서 그래픽이 깨진 적 있음 — 몸 갈아타기 스튜디오).
2. 마일스톤마다: 기획(📐) → 디자인(🎨) → 개발 → FUN QA(🧪) → PM QC(📋). 완료 기준·QC를 다 넘으면 PM이 **"오너 빌드 테스트 준비 완료"** 선언.
3. 그 사이클에만 `PushNotification`(무엇을 테스트할지 3줄 + 전체 주소 https://derrick1119.github.io/derrickkim1119/studio/{{ID}}/) 하고 STATUS `상태: 오너 테스트 대기`. 기다리는 동안은 새 기능을 만들지 않는다(한 줄 보고).
4. 오너가 **통과**라고 하면 다음 마일스톤. **허들 미달**이면 오너 피드백을 STATUS·TALK에 그대로 적고, PM이 **마일스톤을 재수립**(무엇을 어떻게 고치고 언제 다시 테스트할지)한 뒤 진행한다.
5. 최종 목표: **상용화 수준** — 출시해도 되는 품질(온보딩·콘텐츠 볼륨·메타·저장·사운드·성능·접근성·모바일). 마지막 마일스톤 통과가 졸업.

## 가드레일
- 수정할 수 있는 곳은 `studio/{{ID}}/`, `web/public/studio/{{ID}}/`, `tests/studio-{{ID}}*.test.ts` **뿐**. 다른 작업장(`arcade/`, `studio/` 다른 게임, `factory/`, `engine/`, `fusion/`, `web/index.html` 등)은 고치지 않는다.
- `npm run verify` 실패 상태로 push 금지(종료 코드로 판정, 출력을 파이프로 거르지 않는다). 테스트 약화·삭제·skip 금지. push가 거절되면 `git pull --rebase origin factory` → verify → push. force push 금지. `factory` 브랜치에만. 다른 팀의 작업 파일을 stash·checkout으로 건드리지 않는다.
- 런타임 의존성 추가 금지(번들은 esbuild 등 개발 도구로). 외부 서비스 가입·결제·광고 SDK 연동 금지. 비밀값을 저장소에 쓰지 않는다.
- 특정 실존 게임의 이름·캐릭터·아트·레벨을 가져오지 않는다. 결정적 시뮬레이션(봇으로 밸런스 측정)을 유지한다.
- 커밋 메시지: "스튜디오 {{NAME}}: <요약>" (모델 이름을 넣지 않는다).
- 연속 3사이클 verify 실패로 push 못 하면 STATUS `상태: BLOCKED` + 이유 + 알림.
