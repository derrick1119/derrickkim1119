# 발견 공장 가설 백로그

맨 위부터. 한 사이클에 하나 (탐색·재미 A|B·계기판 갱신은 별도로 매 사이클).

- [x] **재미 지표 + A|B 루프 + 계기판 아티팩트** (0003, 오너 요청)
- [x] **필수성 우선 최소화** (0004: `requireAllAtoms` 옵션, A|B 퍼즐에 사용. 발견: 연결성은 쉬움·보통에서 구조적으로 장식 — 비가정 기법이 없음): 생성기가 단서를 지울 때, 끝난 퍼즐에서 필수성이 0인 원자가 있으면 다른 시드로 재시도(최대 k회). 연결성·no2x2 계열 필수성이 오르는지, 생성 시간이 2초 안인지 측정. 기존 발견은 `--only`로 재평가. 출시된 데일리는 파일이 고정이라 영향 없음.
- [x] **이해도** (0005, 오너 피드백 "너무 복잡해서 이해하기 어렵다"): 재미에 이해도(가중치 2) 추가, 도전자 자격 이해도 ≥ 0.7.
- [x] **쉬운 원자 늘리기** (0006: diag4·kline1 추가 → 자격 후보 4→13): 이해도 자격을 통과하는 발견이 4개뿐(십자×반반, 지뢰×줄마다 둘, 지뢰×별, 룩×텅 빈 2×2 금지). 머릿속에 바로 그려지는 새 원자를 추가: "같은 줄 바로 옆 2칸", "십자 4칸 + 자기 칸(5칸)", "덩어리 크기" 등. 각 원자에 친숙도 값을 같이 단다.
- [x] **쉬운 원자 3탄 — 같은 가로줄** (0007)
- [~] **3×3 안 칠한 칸 수(자기 칸 포함)** — 보류(0008): 숫자 칸을 칠할 수 있다는 예외 규칙이 생겨 단순함과 반대: 숫자 칸도 칠할 수 있어야 함 → engine 모델이 숫자 칸을 잠그는지 확인부터. 잠근다면 fusion 쪽 RuleSet에서 숫자 칸을 칠할 수 있게 하는 방법 견적.
- [x] **규칙 문장 다듬기** (0008: 계기판에 예시 그림. 제품은 아래 항목): 2줄 규칙을 30초 안에 이해할 수 있게 예시 그림(3×3 미니 판) 붙이기 — 계기판·교차점 공통.
- [x] **교차점 제품에도 규칙 예시 그림** (0009: gzip +0.83KB, e2e 통과): `fusion/examples.ts`를 `web/fusion/main.ts` 규칙 목록에 붙인다. 번들 +2KB 이내, 390px·다크 확인, fusion:e2e 스크린샷.
- [ ] **탐색 우선순위를 이해도 순으로**: 0008 정규 탐색 새 발견 10개가 전부 자격 미달. 미시험 조합 큐를 이해도 높은 것부터 돌리면 자격 후보가 빨리 는다 (cli-search 큐 정렬 옵션 `--clear-first`).
- [ ] **계기판에서 A|B 고르기 버튼**: 발명 공장 계기판처럼 아티팩트 DB(`ab/round-<N>`)에 오너 선택을 저장하고, 사이클 시작 때 `db_get`으로 읽어 `cli-ab.ts choose`. 채팅 답도 계속 받는다. `describe_capabilities`로 가능 여부부터.
- [ ] **연결성 비가정 기법(끊김 점)**: "이 칸을 칠하면 확정 빈칸(또는 칠한 칸)들이 갈라진다 → 반대로 확정"을 trial이 아닌 pair급 단계로 인정하는 fusion 전용 추론 단계. engine은 발명 공장 소유라 fusion 쪽 래퍼로(추가만). 측정: 연결성 조합의 보통 난이도 필수성 0 → ?
- [ ] **재미 가중치 보정**: A|B 이력이 3건 이상 쌓이면, 오너 선택을 가장 잘 맞히는 가중치를 찾아(로지스틱 회귀, 항목 6개) `FUN_WEIGHT` 후보로 실험. 기계 추천 적중률을 계기판에 표시.
- [ ] **재미 항목 추가 후보 — 첫 수 찾기**: 시작 상태에서 single로 바로 둘 수 있는 칸 수(입구가 몇 개인가). 0이면 막막, 너무 많으면 싱거움.

- [x] **연결성의 누명 벗기기** (0002: 누명 아님 — 융합도 0.8~0.9로 추론기는 연결성을 이미 씀. 원인은 필수성 0.27~0.5. 부산물: kingtouch⇒conne 포함 관계 증명·제외): conne/connf가 장식 판정을 받는 이유가 원자 자체인지, 사람식 추론기에 연결성 기법(분리점: "이 칸을 칠하면 빈칸이 끊긴다")이 없어서인지 구분. 분석기에서 trial 깊이 0의 전역 모순을 별도 기법으로 집계해 비교.
- [ ] **connf × nothree 생성 실패 규명**: 원장에서 connf+nothree 조합이 전부 생성 실패(12/12). 원리상 가능한 조합(칠한 칸 연결 + 셋 연속 금지)인데 샘플러 DFS가 못 찾는 건지 확인. 샘플러 문제면 연결성 인지 샘플링(가지 뻗기) 추가.
- [ ] **탐색 시간 예산 지키기**: `--max-sec 420`인데 0002 탐색은 894초(확증 n=8 평가가 루프 시간 검사 뒤에 돎). 확증 전에 남은 시간을 보고 확증을 다음 사이클로 미루는(원장에 `pendingConfirm`) 방식 검토.
- [ ] **원자 빈도 분석**: 원장으로 원자별 "발견 기여도"(그 원자가 포함된 조합의 발견 비율)와 원자 쌍 궁합표를 만들어 `fusion/reports/atoms.json`에 쓰고 STATE에 요약. 다음 원자 추가 방향을 데이터로 정한다.
- [ ] **원자 추가 1 — 토러스**: 판의 가장자리가 반대편과 이어지는 변형을 '판 원자'로 추가 (모든 이웃 계산이 감싸짐). 새 원자 id로만.
- [ ] **원자 추가 2 — 영역**: 판을 무작위 영역으로 나누고 "영역마다 정확히 1칸" (스타배틀식). 퍼즐 데이터에 영역 배치 추가 필요 — 엔진 변경 없이 fusion 쪽에서 가능한지 견적부터.
- [ ] **교차점 UI: 재료 설명 카드** — 첫 방문 시 "오늘의 재료" 칩을 누르면 원자의 출처 장르와 한 줄 설명을 보여준다.
- [ ] **교차점 PWA·OG 메타** — 공유 미리보기 카드.
- [ ] **발견의 계보**: 상위 발견끼리 원자 하나씩 교환한 자식 조합을 우선 탐색 큐에 넣는 옵션 (`--breed`).
